1. Что это такое

SimpleXLSX — это чистый PHP-ридер xlsx, предназначенный для разбора рабочих книг Microsoft Excel 2007+ формата .xlsx и получения данных ячеек в виде PHP-массива.

Его главное преимущество в одном предложении: не зависит ни от каких дополнительных PHP-расширений — для чтения Excel достаточно встроенных SimpleXML + zlib.

Что он умеет

Возможность Описание
Чтение значений ячеек Текст, числа, булевы значения, даты, значения ошибок, форматированный текст
Несколько листов Доступ по индексу/имени, распознавание скрытых листов, распознавание активного листа
Извлечение стилей Шрифт, цвет, заливка, границы, выравнивание, высота строк и ширина столбцов
Гиперссылки и примечания Внешние ссылки ячеек, внутренние переходы, текст примечаний
Потоковое чтение Генератор readRows(), подходит для больших файлов
Экспорт в HTML toHTML() / toHTMLEx() — преобразование в таблицу одной командой
Ноль зависимостей от расширений Ни php-zip, ни php-excel, распаковка реализована на чистом PHP

Чего он не умеет

Этот момент важнее, чем «что он умеет»; сразу проясним, чтобы сэкономить вам полдня:

Не входит в возможности Причина
Запись/создание xlsx Библиотека только для чтения. Для записи используйте сопутствующую SimpleXLSXGen
Чтение старого формата .xls Совершенно другой бинарный формат, используйте SimpleXLS
Вычисление формул Возвращает только кэшированные результаты, сохранённые Excel на момент сохранения, без пересчёта формул
Информация об объединённых ячейках Не разбирает mergeCells; в объединённой области значение имеет только левая верхняя ячейка
Изображения/диаграммы/сводные таблицы Полностью игнорируются
Условное форматирование, проверка данных Не разбираются
«Исходные фрагменты форматированного текста» ячейки Форматированный текст склеивается в одну строку (см. parseRichText)
Чтение .xlsb / зашифрованных файлов Ни бинарный формат, ни зашифрованный ZIP не поддерживаются

Выбор в одном предложении: если ваша задача — «пользователь загружает Excel, я читаю таблицу и сохраняю в базу данных», SimpleXLSX — самый выгодный выбор (несколько десятков КБ, без зависимостей, достаточно быстрый). Если вам нужно «генерировать сложные отчёты с диаграммами» или «точно воспроизводить печатные стили» — берите PhpSpreadsheet.

2. Требования к окружению и установка

2.1 Системные требования

Требование Описание
PHP >= 5.5 (на PHP 8.3 проверено, работает нормально; в PHP 5.5+ используется совместимый вариант с Generator)
ext-simplexml Обязательно, разбор XML
ext-zlib Обязательно, gzinflate() распаковывает записи ZIP
ext-libxml Обязательно
ext-mbstring Обязательно (заявлено в composer), для ветки совместимости func_overload

Примечание: ext-zip не требуется. Распаковку ZIP автор написал вручную (см. метод unzip()). Именно поэтому библиотека работает на различных дешёвых виртуальных хостингах.

2.2 Способ установки 1: Composer (рекомендуется)

composer require shuchkin/simplexlsx

Затем:

require_once 'vendor/autoload.php';

use Shuchkin\SimpleXLSX;

if ( $xlsx = SimpleXLSX::parse('book.xlsx') ) {
    print_r( $xlsx->rows() );
} else {
    echo SimpleXLSX::parseError();
}

⚠️ Внимание: в autoload файла composer.json зарегистрирован только src/SimpleXLSX.php: json "autoload": { "classmap": ["src/SimpleXLSX.php"] } Файл SimpleXLSXEx.php в classmap не зарегистрирован, он вручную загружается через require_once __DIR__.'/SimpleXLSXEx.php' при вызове readRowsEx(). Вам не нужно об этом заботиться, но и не рассчитывайте, что class_exists('Shuchkin\SimpleXLSXEx') вернёт true, если rowsEx() ни разу не вызывался.

2.3 Способ установки 2: подключение одного файла

Подходит для окружений, где нельзя установить Composer:

require_once __DIR__ . '/src/SimpleXLSX.php';

use Shuchkin\SimpleXLSX;

SimpleXLSX.php самодостаточен и не зависит от других файлов (если только вам не нужен rowsEx()).

2.4 Использование во фреймворках

Laravel: после установки через composer используйте напрямую, ServiceProvider не нужен.

use Shuchkin\SimpleXLSX;

public function import(Request $request) {
    $request->validate(['file' => 'required|file|mimes:xlsx|max:10240']);
    $xlsx = SimpleXLSX::parse($request->file('file')->getRealPath());
    // ...
}

ThinkPHP / другие: подойдёт как require пути к файлу, так и composer autoload.

3.2 Три способа открытия

// ① Из пути к файлу (самый частый случай)
$xlsx = SimpleXLSX::parse('/path/to/book.xlsx');
$xlsx = SimpleXLSX::parseFile('/path/to/book.xlsx');   // эквивалентная запись

// ② Из бинарных данных в памяти
$data = file_get_contents('https://example.com/book.xlsx');
// или извлечь из BLOB в базе данных, из кэша Redis
$xlsx = SimpleXLSX::parseData($data);

// ③ Также поддерживается прямая передача URL (внутри идёт file_get_contents, ограничено allow_url_fopen)
$xlsx = SimpleXLSX::parse('https://www.example.com/example.xlsx');

Соотношение трёх способов (правда из исходного кода):

public static function parse($filename, $is_data = false, $debug = false) // ядро
public static function parseFile($filename, $debug = false)  // → parse($filename, false, $debug)
public static function parseData($data, $debug = false)      // → parse($data, true, $debug)

Внутри parse() сначала вызывается unzip(), затем parseEntries(); при успехе возвращается объект SimpleXLSX, при неудаче — false.

3.3 Классический ООП-стиль

Если вам больше нравится «создать объект + проверить состояние», а не «статическая фабрика + проверка на false»:

$xlsx = new SimpleXLSX('books.xlsx');
if ( $xlsx->success() ) {
    foreach ( $xlsx->rows() as $r ) {
        // ...
    }
} else {
    echo 'xlsx error: ' . $xlsx->error();
}

Сигнатура конструктора: __construct($filename = null, $is_data = null, $debug = null).

Разница между двумя стилями: статический parse() при неудаче возвращает false и помещает сообщение об ошибке в статическую переменную; вариант с new всегда возвращает объект, а успех проверяется через success(). Внизу оба вызывают один и тот же unzip().

3.4 Режим отладки

ini_set('error_reporting', E_ALL);
ini_set('display_errors', 1);

if ( $xlsx = SimpleXLSX::parseFile('books.xlsx', true) ) {
    echo $xlsx->toHTML();
} else {
    echo SimpleXLSX::parseError();
}

После включения $debug = true каждый внутренний вызов error() дополнительно вызывает trigger_error(..., E_USER_WARNING), что упрощает поиск проблем.

4. Ключевые концепции: как xlsx читается

Чтобы по-настоящему эффективно использовать эту библиотеку (особенно при поиске проблем), стоит потратить 3 минуты на понимание её рабочего процесса.

4.1 xlsx по сути является ZIP

.xlsx — это просто ZIP-архив с изменённым расширением, внутри — набор XML:

book.xlsx
├── _rels/.rels                        ← входная точка, указывает, где workbook
├── xl/
│   ├── workbook.xml                   ← список листов, имена, порядок, активный лист
│   ├── _rels/workbook.xml.rels        ← отображение rId → фактические файлы
│   ├── sharedStrings.xml              ← пул общих строк
│   ├── styles.xml                     ← шрифты/заливки/границы/числовые форматы
│   ├── theme/theme1.xml               ← цвета темы
│   └── worksheets/
│       ├── sheet1.xml                 ← сами данные ячеек
│       ├── _rels/sheet1.xml.rels      ← гиперссылки/примечания этого листа
│       └── ...

4.2 Процесс разбора (соответствует методам исходного кода)

SimpleXLSX::parse($file)
    │
    ├─ unzip($filename, $is_data)      ← самописная распаковка ZIP, все записи читаются в $this->package['entries']
    │                                     (на этом этапе не распаковываются, сохраняются только сжатые данные + заголовки)
    │
    └─ parseEntries()                  ← построение индексов
         ├─ читает _rels/.rels → находит officeDocument → xl/workbook.xml
         ├─ обходит <sheet> в workbook.xml → $this->sheetMetaData[i] (name/sheetId/state/id)
         ├─ читает xl/_rels/workbook.xml.rels → распределяет по rId:
         │     worksheet    → $this->sheets[i] = SimpleXMLElement (и запоминает sheetFiles[i])
         │     sharedStrings→ $this->sharedstrings[] = массив строк
         │     styles       → $this->styles + $this->nf + $this->cellFormats
         │     theme        → $this->theme
         └─ из <bookViews><workbookView activeTab="N"> в workbook.xml берёт $this->activeSheet

4.3 Модель памяти (важно)

На этом многие спотыкаются:

  1. unzip() одним вызовом file_get_contents() читает весь файл в память;
  2. Все записи ZIP (в сжатом виде) полностью сохраняются в массиве $this->package['entries'];
  3. Только при вызове getEntryXML($name) выполняется распаковка gzinflate(), и сразу после распаковки запись удаляется из массива через deleteEntry() (экономия памяти);
  4. Но sheet1.xml, разобранный simplexml_load_string() в SimpleXMLElement, постоянно остаётся в памяти.

Вывод: пиковое потребление памяти как минимум в 2–3 раза больше размера файла, плюс дерево объектов XML. readRows() экономит только уровень «массива результатов», но не уровень «DOM всего листа». Подробности в главе 10.

4.4 Координаты ячеек

  • Взаимное преобразование стиля A1 (запись Excel) и [индекс столбца, индекс строки] (0-based):
  • getIndex('AB12') → [27, 11] (проверено)
  • SimpleXLSX::num2name(3) → 'C'
  • num2name(1) = 'A', num2name(27) = 'AA' (проверено)

5. Полный справочник API

Все приведённые ниже сигнатуры получены рефлексией из исходного кода 1.1.19, значения параметров по умолчанию полностью совпадают с исходным кодом.

5.1 Статические фабричные методы

SimpleXLSX::parse($filename, $is_data = false, $debug = false)

Параметр Тип Описание
$filename string Путь к файлу, URL, а при $is_data=true — бинарное содержимое xlsx
$is_data bool true означает, что первый параметр — данные, а не путь
$debug bool При включении ошибки вызывают trigger_error

Возврат: при успехе объект SimpleXLSX, при неудаче false.

$xlsx = SimpleXLSX::parse('book.xlsx');          // файл
$xlsx = SimpleXLSX::parse($binary, true);        // данные в памяти
$xlsx = SimpleXLSX::parse('a.xlsx', false, true);// отладка

SimpleXLSX::parseFile($filename, $debug = false)

Эквивалентно parse($filename, false, $debug). Семантически понятнее, рекомендуется.

SimpleXLSX::parseData($data, $debug = false)

Эквивалентно parse($data, true, $debug). Для BLOB в базе данных / кэша / сетевых потоков.

SimpleXLSX::parseError($set = false) / SimpleXLSX::parseErrno($set = false)

Читает (или устанавливает) сообщение об ошибке/код ошибки последнего parse().

if ( !$xlsx = SimpleXLSX::parse('x.xlsx') ) {
    echo SimpleXLSX::parseErrno() . ': ' . SimpleXLSX::parseError();
}

⚠️ Эти два метода используют static локальные переменные — это глобальное разделяемое состояние. При последовательном разборе нескольких файлов обязательно считывайте результат сразу после каждого parse(), иначе он будет перезаписан следующим разбором.

Метод Возврат Описание

sheetName($i) string|false Получить имя по индексу

Проверенный вывод:

$x = SimpleXLSX::parse('types.xlsx');
print_r($x->sheetNames());
// Array( [0] => Тест типов [1] => Вторая страница [2] => Скрытая страница )

print_r($x->sheetMeta());
// Array(
//   [0] => Array( [name] => Тест типов [sheetId] => 1 [state] => visible [id] => rId1 )
//   [1] => Array( [name] => Вторая страница   [sheetId] => 2 [state] => visible [id] => rId2 )
//   [2] => Array( [name] => Скрытая страница   [sheetId] => 3 [state] => hidden  [id] => rId3 )
// )

var_dump($x->isHiddenSheet(2)); // true

Найти индекс по имени (библиотека этого не предоставляет, пишем сами):

function sheetIndexByName(SimpleXLSX $xlsx, string $name): ?int {
    $map = array_flip($xlsx->sheetNames());
    return $map[$name] ?? null;
}

💡 Ключи массива sheets отсортированы в порядке появления <sheet> в workbook.xml, и в конце parseEntries() выполняется ksort(), поэтому индексы стабильно соответствуют порядку ярлыков в Excel слева направо.

5.4 Чтение данных (ядро)

rows($worksheetIndex = 0, $limit = 0): array

Самый часто используемый метод. Возвращает двумерный массив, каждая строка — численно индексированный массив, начиная со столбца 0.

Параметр Описание
$worksheetIndex Индекс листа, 0-based
$limit Максимальное количество возвращаемых строк; 0 — без ограничения 
foreach ( $xlsx->rows() as $r ) {
    echo $r[0] . ' | ' . $r[1] . "\n";
}

Внутренняя реализация: iterator_to_array($this->readRows(...), false), то есть всё сразу разворачивается в массив.

Поведение дополнения пустыми строками: readRows() дополняет хвостовые пустые строки по количеству строк из dimension(). То есть если <dimension> Excel объявляет 100 строк, а данные есть только в 3, вы получите 100 строк (последние 97 — массивы пустых строк).

readRows($worksheetIndex = 0, $limit = 0): Generator

Возвращает те же данные, что и rows(), но это генератор, выдающий строки по одной, без расхода памяти на массив результатов.

foreach ( $xlsx->readRows() as $k => $r ) {
    fputcsv($fp, $r);
}

rowsEx($worksheetIndex = 0, $limit = 0): array

Расширенная версия, каждая ячейка — ассоциативный массив из 16 полей (значение + стиль + гиперссылка + примечание + формула и т.д.). Подробности в главе 6.

При первом вызове через require_once загружается SimpleXLSXEx.php и создаётся экземпляр SimpleXLSXEx (кэшируется в $xlsx->rowsExReader).

readRowsEx($worksheetIndex = 0, $limit = 0): Generator

Версия rowsEx() на генераторе.

🔴 Проверенный баг: $limit не работает, когда он меньше числа строк листа (возвращается полное число строк, лишние — пустые). Подробности в ловушке 1. Считайте сами и прерывайте через break.

getCell($worksheetIndex = 0, $cell = 'A1'): mixed

Получает значение одной ячейки по координате Excel.

echo $xlsx->getCell(0, 'B2');     // The Hobbit
echo $xlsx->getCell(0, [1, 2]);   // эквивалентно, [индекс столбца, номер строки], столбцы 0-based, строки 1-based

⚠️ Предупреждение о производительности: в комментарии исходного кода прямо написано VERY SLOW!. Внутри используется $ws->sheetData->xpath("row/c[@r='B2']") — полный проход по таблице XPath, каждый вызов — новый проход. Никогда не используйте в цикле. Чтобы получить несколько ячеек, один раз вызовите rows() и берите по индексам.

Если ячейка не найдена, возвращается null; если лист не существует — false.

dimension($worksheetIndex = 0): array

Возвращает [число столбцов, число строк].

list($cols, $rows) = $xlsx->dimension(0);

Логика определения типа (ключевые моменты исходного кода)

// 1) Если тип пуст или n, определяется, является ли значение датой, по строке числового формата в стиле
if ($dataType === '' || $dataType === 'n') {
    $s = (int)$cell['s'];
    if ($s > 0 && isset($this->cellFormats[$s])) {
        if (array_key_exists('format', $this->cellFormats[$s])) {
            $format = $this->cellFormats[$s]['format'];
            // Если после удаления литералов в кавычках строка формата содержит m (месяц/минута), считается датой
            if ($format && preg_match('/[mM]/', preg_replace('/"[^"]+"/', '', $format))) {
                $dataType = 'D';
            }
        }
    }
}

// 2) Ветвь по умолчанию: строка, при возможности преобразуется в число
$value = (string)$cell->v;
if (is_numeric($value)) {
    if ($value == (int)$value)   $value = (int)$value;
    elseif ($value == (float)$value) $value = (float)$value;
}

Это означает:

  1. Определение даты зависит от «наличия буквы m в коде формата». Если числовой столбец в таблице ошибочно получил пользовательский формат с m, он будет ошибочно преобразован в дату. И наоборот, если столбцу дат назначен General, будет возвращено дробное серийное значение даты Excel (например 44613.0), а не дата.
  2. Ведущие нули теряются. Например 007 (воспринятое как число) превратится в 7. Номера телефонов, ID-номера и почтовые индексы в Excel обязательно нужно задавать в текстовом формате, иначе SimpleXLSX вернёт int/float. Это источник данных-инцидентов №1 при импорте в системы.
  3. Точность больших целых чисел: при превышении диапазона PHP int или при наличии дробной части преобразуется во float, 1234567890123456789 может превратиться в 1.2345678901235E+18.

О «чистом времени»

Время без даты в Excel (например 13:41:00) хранится как 0.570138... (целая часть равна 0). Для d == 0 метод unixstamp() идёт по особой ветке:

$t = (abs($d) > 0) ? ($d - 25569) * 86400 + round($t * 86400) : round($t * 86400);

В результате отсчёт идёт от эпохи Unix (1970-01-01), поэтому 13:41 → '1970-01-01 13:41:00' (подтверждено на практике).

Практическое решение для бизнес-логики: брать только часть времени.

$val = $cell['value'];               // '1970-01-01 13:41:00'
$time = substr($val, 11);            // '13:41:00'

О формулах

SimpleXLSX не вычисляет формулы, он читает кэшированный результат, сохранённый Excel в файле (<v> внутри <c><f>B3*2</f><v>1236</v></c>).

Обнаружено на практике: xlsx, созданные openpyxl и частью не-Excel инструментов, не записывают кэшированное значение; в этом случае value — пустая строка, содержимое есть только в f.

Рекомендации по обработке:

foreach ($xlsx->rowsEx() as $row) {
    foreach ($row as $c) {
        $v = $c['value'];
        if ($v === '' && $c['f'] !== '') {
            // Ячейка с формулой без кэшированного значения
            $v = null; // или пометить для ручной обработки / пересчитать самостоятельно
        }
    }
}

8. Тема дат и времени

8.1 Природа дат Excel

Дата в Excel — это число с плавающей точкой: целая часть — «количество дней с 1899-12-30» (система 1900), дробная часть — доля прошедших суток. Например 42472.570138889 = 2016-04-12 13:41:00.

Почему 1899-12-30, а не 1900-01-01? Потому что в Excel есть знаменитый баг «1900 год — високосный». Число 25569 в unixstamp() — это разница в днях между 1899-12-30 и 1970-01-01.

8.2 Формула преобразования

public function unixstamp($excelDateTime) {
    $d = floor($excelDateTime);      // количество дней
    $t = $excelDateTime - $d;        // доля суток
    if ($this->date1904) { $d += 1462; }   // для системы 1904 добавляется 1462 дня
    $t = (abs($d) > 0) ? ($d - 25569) * 86400 + round($t * 86400) : round($t * 86400);
    return (int)$t;
}

Затем форматирование через gmdate($this->datetimeFormat, $ts) — обратите внимание: используется gmdate(), а не date(), то есть метка времени интерпретируется по UTC.

8.3 Четыре варианта использования

$xlsx = SimpleXLSX::parse('book.xlsx');

// ① По умолчанию: формат ISO (можно напрямую сохранять в MySQL DATETIME)
echo $xlsx->getCell(0, 'C2');   // 2016-04-12 13:41:00

// ② Пользовательский формат
$xlsx->setDateTimeFormat('d.m.Y H:i');
echo $xlsx->getCell(0, 'C2');   // 12.04.2016 13:41

// ③ Метка времени Unix
$xlsx->setDateTimeFormat('U');
$ts = $xlsx->getCell(0, 'C2');  // 1645401600 (строка)
echo gmdate('Y-m-d', $ts);      // 2016-04-12

// ④ Исходное серийное значение Excel (отказ от автоматического преобразования)
$xlsx->setDateTimeFormat(null);
$xd = $xlsx->getCell(0, 'C2');  // 42472.570138889 (float)
echo gmdate('m/d/Y', $xlsx->unixstamp($xd));  // 04/12/2016

Проверено на практике (одна и та же ячейка, четыре настройки):

NULL             => 44613.0                      (float)
'Y-m-d H:i:s'    => '2022-02-21 00:00:00'        (string)
'd.m.Y H:i'      => '21.02.2022 00:00'           (string)
'U'              => '1645401600'                 (string)

Обратите внимание: 'U' возвращает строку, а не целое число, требуется приведение (int).

8.4 Ловушка часовых поясов

gmdate() означает: если в Excel записано 2016-04-12 13:41, то на выходе будет 2016-04-12 13:41:00, без смещения из-за часового пояса сервера. Обычно это именно то, что нужно (что видно в Excel, то и получаете).

И наоборот, если нужно интерпретировать по определённому часовому поясу, смещение нужно добавить самостоятельно:

$xlsx->setDateTimeFormat('U');
$ts = (int)$xlsx->getCell(0, 'C2');
$local = date('Y-m-d H:i:s', $ts + 8 * 3600);  // отображение по восточно-китайскому поясу (UTC+8)

8.5 Система дат 1904

Старые файлы Mac-версии Excel могут использовать систему 1904. Библиотека автоматически определяет это по <workbookPr date1904="1"> в workbook.xml и устанавливает $xlsx->date1904 = 1.

Если требуется ручное вмешательство (свойство public):

$xlsx->date1904 = 1;   // принудительно использовать систему 1904

Если вы обнаружили, что все даты на 4 года и 1 день позже реальных, это именно та проблема.

8.6 Вспомогательная функция распознавания столбцов с датами

rows() даёт только значения и не сообщает, какой столбец содержит даты. Определяйте по format из rowsEx():

function isDateCell(array $cell): bool {
    if ($cell['type'] === 'd') return true;
    if (!in_array($cell['type'], ['', 'n'], true)) return false;
    $fmt = preg_replace('/"[^"]+"/', '', $cell['format']);
    // содержит любую из букв y/m/d/h/s и не является чисто числовым форматом
    return (bool)preg_match('/[ymdhs]/i', $fmt);
}

9. Система стилей (SimpleXLSXEx)

9.1 Момент загрузки

SimpleXLSXEx — ленивая загрузка: класс подключается через require_once и инстанцируется только при первом вызове rowsEx() / readRowsEx() / toHTMLEx(), после чего кэшируется в $xlsx->rowsExReader.

Если вы используете только rows(), этот класс вообще не будет загружен — нулевые накладные расходы.

9.2 Что делается в конструкторе

public function __construct(SimpleXLSX $xlsx) {
    $this->readThemeColors();  // палитра темы (12 цветов)
    $this->readFonts();        // fonts: b/i/u/strike/sz/color/name/family/charset/scheme
    $this->readFills();        // fills: pattern/fgcolor/bgcolor
    $this->readBorders();      // borders: 8 направлений + diagonalUp/Down/outline
    $this->readXfs();          // объединяется в $this->css[s] и дополняются cellFormats
    $this->readHyperlinks();   // карта гиперссылок по листам
    $this->readComments();     // карта примечаний по листам
}

9.3 Разбор цвета getColorValue()

Поддерживается приоритет трёх представлений цвета Excel:

  1. rgb="FFCCBBAA" → берутся последние 6 символов (alpha отбрасывается)
  2. indexed="N" → поиск во встроенной палитре SimpleXLSXEx::$IC (65 цветов)
  3. theme="N" → поиск в палитре темы

В конце, если присутствует атрибут tint, выполняется смешивание оттенка (интерполяция к белому/чёрному).

9.5 Пересчёт размера шрифта

$css .= 'font-size: ' . (round($cf['f-size'] * 1.3333) + 2) . 'px;';

Единица размера шрифта в Excel — пункт (pt), здесь грубое преобразование в px: pt × 1.3333 + 2 (1pt ≈ 1.333px). Поэтому шрифт 11 → 17px, 14 → 21px.

9.6 Границы

14 стилей границ Excel упрощены до двух CSS: solid и dashed (dashed/dashDot/dashDotDot → dashed, остальные не none → solid), толщина везде thin, цвет берётся из цвета соответствующего направления.

То есть: medium, thick, double, hair в HTML выглядят одинаково. Это намеренное упрощение, не рассчитывайте на попиксельное воспроизведение.

9.7 Самостоятельная генерация CSS (обход бага встроенного css)

Если встроенного поля css недостаточно (см. баг накопления в главе 13), можно напрямую читать cellFormats и собирать CSS самому:

function buildCss(SimpleXLSX $xlsx, int $s): string {
    $f = $xlsx->cellFormats[$s] ?? [];
    $css = '';
    if (!empty($f['color']))    $css .= 'color:#' . $f['color'] . ';';
    if (!empty($f['bgcolor']))  $css .= 'background-color:#' . $f['bgcolor'] . ';';
    if (!empty($f['f-b']))      $css .= 'font-weight:bold;';
    if (!empty($f['f-i']))      $css .= 'font-style:italic;';
    if (!empty($f['align']))    $css .= 'text-align:' . $f['align'] . ';';
    if (!empty($f['valign']))   $css .= 'vertical-align:' . $f['valign'] . ';';
    if (!empty($f['f-size']))   $css .= 'font-size:' . (round($f['f-size'] * 1.3333) + 2) . 'px;';
    return $css;
}

10. Большие файлы и оптимизация памяти

10.1 Официальные эталонные данные

Практические измерения автора в CHANGELOG 1.0.12:

Способ Потребление памяти на 100 тыс. строк
rowsEx() ~880 MB
readRowsEx() ~162 MB

Разница более чем в 5 раз. Причина в том, что rows() / rowsEx() разворачивают весь лист в огромный двумерный массив PHP (каждый элемент массива PHP стоит примерно 80–100 байт; 100 тыс. × 10 столбцов — это миллион zval).

10.2 Куда уходит память

Всего памяти ≈ размер файла (исходный бинарник)
       + сжатые данные всех записей ZIP (package['entries'])
       + дерево SimpleXMLElement разобранных листов (самая большая часть)
       + массив общих строк
       + результирующий массив (только у rows/rowsEx)

readRows() отсекает только последний пункт.

10.3 Список оптимизаций

① В первую очередь используйте генераторы

// ❌ Плохо: вся таблица попадает в память
foreach ($xlsx->rows() as $r) { ... }

// ✅ Хорошо: построчная выдача
foreach ($xlsx->readRows() as $r) { ... }

② Пишите в целевой поток, не накапливайте

$f = fopen('out.csv', 'wb');
fwrite($f, chr(0xEF) . chr(0xBB) . chr(0xBF));  // BOM UTF-8, чтобы Excel не показывал иероглифы вместо китайского
foreach ($xlsx->readRows() as $r) {
    fputcsv($f, $r);
}
fclose($f);

③ Обрабатывайте порциями и освобождайте ресурсы

$pdo->beginTransaction();
$stmt = $pdo->prepare('INSERT INTO t (a,b,c) VALUES (?,?,?)');
$i = 0;
foreach ($xlsx->readRows() as $k => $r) {
    if ($k === 0) continue;                 // пропустить заголовок
    $stmt->execute([$r[0], $r[1], $r[2]]);
    if (++$i % 1000 === 0) {
        $pdo->commit(); $pdo->beginTransaction();
    }
}
$pdo->commit();

④ Повысьте лимит памяти (крайняя мера)

ini_set('memory_limit', '512M');

⑤ Практический совет для очень больших таблиц

Если xlsx превышает 20–30 MB или 500 тыс. строк, SimpleXLSX — неподходящий инструмент, потому что XML DOM обязан целиком находиться в памяти. В этом случае следует:

  • на этапе загрузки предложить пользователю передавать CSV;
  • либо написать самостоятельно с потоковым SAX-парсером (например XMLReader + expand());
  • либо использовать PhpSpreadsheet с setReadDataOnly(true) + чтение частями (chunk) (тоже расходует память, но немного лучше).

10.4 Параметр $limit (⚠️ поведение методов несогласовано)

rows() / readRows() / rowsEx() / readRowsEx() все объявляют $limit, но по проверкам надёжны только первые три:

$xlsx->rows(0, 100);        // ✅ только первые 100 строк
$xlsx->readRows(0, 100);    // ✅ нормально
$xlsx->rowsEx(0, 100);      // ✅ нормально (внутри идёт через iterator_to_array)
$xlsx->readRowsEx(0, 100);  // ❌ не работает, возвращает все строки

Проверенное граничное поведение readRows() (в таблице всего 13 строк):

$limit Количество возвращённых строк
0 13 (без ограничения)
1 1
2 2
99 13

В тех же условиях readRowsEx() при передаче 1/2/3/5 всегда возвращает 13 строк. Причина и способ обхода — см. ловушку 1.

⚠️ У toHTML() и toHTMLEx() параметра $limit вообще нет (в исходном коде только 1 параметр).

12. Вопросы безопасности

12.1 XSS: значения экранированы, но href — нет

Хорошая новость: toHTML() и toHTMLEx() применяют htmlspecialchars($v, ENT_QUOTES) ко всем значениям ячеек.

Плохая новость: поле href, возвращаемое rowsEx(), не проходит никакой проверки протокола. Если вы сами собираете HTML:

// ❌ Опасно: href может быть javascript:alert(1)
echo '<a href="' . $cell['href'] . '">link</a>';

// ✅ Правильно: проверка по белому списку
function safeHref(string $href): string {
    if (preg_match('#^https?://#i', $href)) return $href;
    if (preg_match('#^mailto:#i', $href))   return $href;
    if (preg_match('/^[^!]+![A-Z]+\d+$/', $href)) return ''; // внутренний переход, в HTML выразить невозможно
    return '';
}
echo '<a href="' . safeHref($cell['href']) . '">link</a>';

12.2 CSS-инъекция (CVE-2024-55878)

В исторических версиях существовала уязвимость инъекции CSS через стили (GHSA-x6mh-rjwm-8ph7). В 1.1.19 исправлено, следующим образом:

  • Имя шрифта жёстко по белому списку: preg_match('/^[a-zA-Z0-9 ]+$/', $name), при недопустимости откат к Calibri
  • Цвет жёстко 6-значный hex: preg_match('/^[A-F0-9]{6}$/', $c)
  • Значения выравнивания берутся только из фиксированной таблицы соответствия

Но если вы встраиваете поле css напрямую в style="", всё равно рекомендуется повторная санитизация (особенно при рендеринге в публичном интернете файлов, загруженных пользователями):

// Грубая фильтрация: оставляем только заведомо безопасные CSS-свойства
function sanitizeCss(string $css): string {
    $out = '';
    foreach (explode(';', $css) as $decl) {
        $decl = trim($decl);
        if (preg_match('/^(color|background-color|font-family|font-size|font-weight|font-style|text-decoration|text-align|vertical-align|border-(top|right|bottom|left)-(style|color|width)):/', $decl)) {
            $out .= $decl . ';';
        }
    }
    return $out;
}

Более основательное решение: подключить HTMLPurifier.

12.3 XXE (внешние XML-сущности)

В исходном коде уже обработано:

if (LIBXML_VERSION < 20900 && function_exists('libxml_disable_entity_loader')) {
    $_old = libxml_disable_entity_loader();
}
$entry_xmlobj = simplexml_load_string($entry_xml, 'SimpleXMLElement', LIBXML_COMPACT | LIBXML_PARSEHUGE);

libxml >= 2.9 по умолчанию не загружает внешние сущности, ручное отключение не требуется. При условии, что вы используете достаточно новую версию libxml, — не запускайте без защиты на старых системах вроде CentOS 6.

12.4 Zip-бомба (Zip Bomb)

xlsx — это ZIP, теоретически существует риск zip-бомбы (файл 1KB распаковывается в 10GB). SimpleXLSX не имеет ограничения на размер распаковки.

Защита: ограничьте размер файла перед загрузкой (например ≤ 10 MB) и установите memory_limit на стороне PHP как подстраховку.

12.5 Прочее

  • Не доверяйте dimension: вредоносный файл может объявить A1:XFD1048576, из-за чего readRows() попытается дополнить сотни миллионов пустых строк. Рекомендуется самостоятельно ограничить число строк.
  • Имена файлов: не собирайте путь из загруженного исходного имени файла (path traversal), генерируйте имя файла сами.
  • Жизненный цикл временных файлов: PHP удаляет временные файлы загрузок после завершения скрипта, обязательно сначала выполните move_uploaded_file().

13. Известные проблемы и список ловушек

Ниже — поведение, обнаруженное при чтении исходного кода и практических проверках, в официальной документации не описанное, сгруппировано по серьёзности (🔴 высокий / 🟠 средний / 🟢 низкий).

🔴 Ловушка 1: параметр $limit у readRowsEx() не работает (подтверждено проверкой на 1.1.19)

Симптом: когда $limit меньше числа строк листа, readRowsEx() игнорирует limit и возвращает полное количество строк (лишние — все пустые).

Проверенные данные (в листе всего 13 строк):

$limit Возвращает readRows() Возвращает readRowsEx()
0 (без ограничения) 13 13
1 1 ✅ 13 ❌
2 2 ✅ 13 ❌
3 3 ✅ 13 ❌
5 5 ✅ 13 ❌
13 13 ✅ 13 ✅
20 13 ✅ 13 ✅

Первопричина: в SimpleXLSXEx::readRowsEx() при достижении limit используется break, а в SimpleXLSX::readRows() — return:

// SimpleXLSX::readRows() — правильно
yield $r;
$_limit--;
if ($_limit === 0) { return; }        // ← генератор сразу завершается

// SimpleXLSXEx::readRowsEx() — баг
yield $cells;
$_limit--;
if ($_limit === 0) { break; }         // ← выход только из foreach
// ...
while ($curR < $numRows) {            // ← после break выполнение всё равно попадает сюда
    yield $emptyRow;                  //    продолжают добавляться пустые строки, причём $_limit уже стал отрицательным и никогда больше не станет 0
    $_limit--;
    if ($_limit === 0) { return; }
}

Последствия: при вызове rowsEx(0, 100) в надежде «предпросмотреть первые 100 строк» на самом деле вы получите все строки таблицы (включая временно добавленные в конце пустые), а на больших файлах потребление памяти и время выполнения выходят из-под контроля.

Обходное решение: считайте строки сами и прерывайте цикл, не полагайтесь на $limit:

$n = 0;
foreach ($xlsx->readRowsEx(0) as $r) {      // не передаём limit
    if (++$n > 100) break;
    // ...
}

✅ Исправлено: патч, прилагаемый к этому документу (см. XVII. Список исправлений багов исходного кода), меняет break на return. После исправления $limit в readRowsEx() ведёт себя так же, как в readRows(), и $limit можно использовать напрямую.

🔴 Подводный камень 2: повторные вызовы rowsEx() у одного экземпляра приводят к бесконечному накоплению CSS

Симптомы (проверено на практике):

1-й вызов rowsEx B3.css = 'color: #000000;font-family: Calibri;font-size: 17px;text-align: right;×4'
2-й вызов rowsEx B3.css = '... text-align: right;×8'
3-й вызов rowsEx B3.css = '... text-align: right;×12'

Причина: в SimpleXLSXEx::valueEx() используется присваивание по ссылке:

$r['css'] = &$this->css[$r['s']];           // ссылка!
if (...) { $r['css'] .= 'text-align: right;'; }  // запись идёт прямо в $this->css[$s]

При каждом вызове rowsEx()/toHTMLEx() ко всем ячейкам, «непустым, без выравнивания и не текстового типа», к одной и той же общей строке добавляется ещё один фрагмент.

Последствия: выводимый HTML растёт, таблица стилей загрязняется (хотя семантически повторяющиеся CSS-объявления безвредны, строка растёт экспоненциально).

Обходное решение:

// Вариант A: каждый раз заново parse (самый простой)
$xlsx1 = SimpleXLSX::parse($f); $a = $xlsx1->rowsEx();
$xlsx2 = SimpleXLSX::parse($f); $b = $xlsx2->rowsEx();

// Вариант B: дедупликация
$css = implode(';', array_unique(array_filter(explode(';', $cell['css'])))) . ';';

// Вариант C: не использовать встроенный css, а генерировать самому по cellFormats (см. 9.7)

✅ Исправлено: сопутствующий патч заменяет присваивание по ссылке на копирование значения ($r['css'] = isset($this->css[$r['s']]) ? ... : ''), при повторных вызовах у одного экземпляра больше ничего не накапливается.

🔴 Подводный камень 2: у toHTML() / toHTMLEx() нет параметра $limit

В README сигнатура указана как toHTML($worksheetIndex = 0, $limit = 0), но по рефлексии в исходном коде фактически только 1 параметр. Передача второго параметра молча игнорируется.

Если нужно ограничить число строк:

echo '<table>';
$i = 0;
foreach ($xlsx->readRowsEx(0, 100) as $r) {   // генератор + limit
    echo '<tr>';
    foreach ($r as $c) { echo '<td>' . htmlspecialchars($c['value']) . '</td>'; }
    echo '</tr>';
}
echo '</table>';

✅ Исправлено: сопутствующий патч добавляет обоим методам параметр $limit и передаёт его в readRows()/readRowsEx(), теперь можно писать toHTML(0, 100) напрямую.

🟠 Подводный камень 3: ячейка с формулой может вернуть пустую строку

Формулы не вычисляются, читаются только кэшированные значения. У xlsx, созданных не в Excel, кэшированного значения часто нет → value === ''. Подробнее см. главу VII.

✅ Решено: сопутствующее расширение SimpleXLSXPro содержит собственный движок вычисления формул и может вычислять результаты даже для формул без кэшированного значения; подробнее см. XVIII. Вычисление формул.

🟠 Подводный камень 4: ведущие нули / потеря точности у длинных чисел

007 и 130123199001011234, сохранённые в Excel как числа, будут преобразованы в int/float — ведущие нули и точность теряются.

Решать нужно в источнике: требуйте от пользователей задать этим столбцам в Excel формат «Текстовый» или дописывайте нули по бизнес-правилам после импорта:

$id = str_pad((string)$v, 18, '0', STR_PAD_LEFT);

🟠 Подводный камень 5: неточный dimension приводит к лишним пустым строкам

После перебора реальных строк readRows() выполняет ещё while ($curR < $numRows) yield $emptyRow;. Если в XML dimension объявляет число строк, намного большее фактического, вы получите кучу полностью пустых строк.

Защита:

$maxRows = 100000;
$n = 0;
foreach ($xlsx->readRows() as $r) {
    if (++$n > $maxRows) break;
    if (array_filter($r) === []) continue;   // пропускаем полностью пустые строки
    // ...
}

🟡 Подводный камень 6: getCell() крайне медленный

Внутри — полный скан таблицы через XPath. В комментарии исходного кода прямо написано VERY SLOW!. При выборке 1000 ячеек через getCell() будут заметные задержки. Для массового получения значений используйте rows() и обращайтесь по индексу.

🟡 Подводный камень 7: parseError() — глобальное статическое состояние

static $error = false;
return $set ? $error = $set : $error;

При циклическом разборе нескольких файлов, если какой-то из промежуточных разборов успешен, parseError() не очищается (ветка успеха не вызывает parseError()). Поэтому:

// ❌ после успешного второго parse читается ошибка от первого
SimpleXLSX::parse('bad.xlsx');   // неудача, устанавливает error
SimpleXLSX::parse('good.xlsx');  // успех, error не сбрасывается
echo SimpleXLSX::parseError();   // по-прежнему показывает ошибку bad.xlsx!

// ✅ правильно: читать только в ветке неудачи
if (!$x = SimpleXLSX::parse('bad.xlsx')) { echo SimpleXLSX::parseError(); }
if (!$x = SimpleXLSX::parse('good.xlsx')) { echo SimpleXLSX::parseError(); }

✅ Исправлено: сопутствующий патч добавляет parseError()/parseErrno() параметр $reset и принудительно обнуляет ошибку в ветке успеха parse(). Проверено после исправления: SimpleXLSX::parse('bad.xlsx') → после неудачи parseError() = 'File not found bad.xlsx'; сразу после успешного parse('good.xlsx') → parseError() = false.

Либо используйте в цикле new SimpleXLSX() + экземплярный метод $xlsx->error() — естественная изоляция.

🟡 Подводный камень 8: при несуществующем листе rows() возвращает пустой массив вместо ошибки

var_dump($xlsx->rows(9));   // array(0) {} — пустой массив, не false
echo $xlsx->errno();        // но errno установлен в 6

Поэтому успешность нельзя определять только по empty($rows), проверяйте errno() или сначала sheetsCount().

🟡 Подводный камень 9: выход индекса стиля за границы вызывает PHP Notice

В valueEx():

$st = &$this->xlsx->cellFormats[$r['s']];

Если в xlsx определений cellXfs меньше, чем индексов s, на которые ссылаются ячейки, будет ошибка Undefined offset. В продакшене рекомендуется отключить вывод notice или подавить его через @ перед вызовом.

✅ Исправлено: сопутствующий патч добавляет перед получением значения защиту через isset(), отсутствующий индекс автоматически заполняется ['format'=>null,'align'=>0].

🟡 Подводный камень 10: объединённые ячейки не возвращаются

mergeCells вообще не разбирается. В объединённой области значение есть только у верхней левой ячейки, остальные пусты. Если вы полагаетесь на эффект «заполнения» объединённых ячеек, придётся обрабатывать самостоятельно:

$last = null;
foreach ($rows as $r) {
    $r[0] = $r[0] !== '' ? $r[0] : $last;   // простое заполнение вниз
    $last = $r[0];
}

✅ Решено: сопутствующее расширение SimpleXLSXPro полностью разбирает mergeCells: в CSV/TSV/JSON значения распределяются копированием по каждой ячейке x*y, в HTML выводятся настоящие colspan/rowspan. Подробнее см. XIX. Объединённые ячейки и мультиформатный экспорт.

🟢 Подводный камень 11: ограничения ZIP64

Начиная с 1.1.18 поддерживаются дескрипторы данных ZIP64, но при одиночном элементе больше 4 ГБ по-прежнему возвращается ошибка 6 "ZIP64 entry is too large to process". Обычные xlsx с этим не сталкиваются.

🟢 Подводный камень 12: очистка префиксов пространств имён регулярными выражениями

getEntryXML() удаляет XML-пространства имён цепочкой регулярок:

$entry_xml = preg_replace('/xmlns[^=]*="[^"]*"/i', '', $entry_xml);
$entry_xml = preg_replace('/[a-zA-Z0-9]+:([a-zA-Z0-9]+="[^"]+")/', '$1', $entry_xml);
$entry_xml = preg_replace('/<[a-zA-Z0-9]+:([^>]+)>/', '<$1>', $entry_xml);

Это подход «грязно, но быстро». Для крайне нестандартного XML возможны ложные срабатывания. Если встретится errno=3, можно вывести очищенный XML для диагностики.

🟢 Подводный камень 13: regex-оптимизация пустых строк

Для XML листа регуляркой удаляются строки, где «вся строка состоит из пустых <c/>»:

$entry_xml = preg_replace('/<row[^>]+>\s*(<c[^\/]+\/>\s*)+<\/row>/', '', $entry_xml, -1, $cnt);

Побочный эффект: номера строк перестают быть непрерывными. rows() восстанавливает пустые строки (по координатам y, вычисленным через getIndex()), поэтому обычно всё в порядке; но если вы напрямую перебираете worksheet()->sheetData->row, учтите, что номера строк идут с пропусками.

Официальный пример, самый употребимый:

function xlsxToAssoc(SimpleXLSX $xlsx, int $sheet = 0): array {
    $header = [];
    $rows   = [];
    foreach ($xlsx->readRows($sheet) as $k => $r) {
        if ($k === 0) { $header = $r; continue; }
        $rows[] = array_combine($header, $r);
    }
    return $rows;
}

Улучшенная версия (обрабатывает разное число столбцов, дублирующиеся заголовки, пустые заголовки):

function xlsxToAssocSafe(SimpleXLSX $xlsx, int $sheet = 0): array {
    $header = [];
    $rows   = [];
    foreach ($xlsx->readRows($sheet) as $k => $r) {
        if ($k === 0) {
            $seen = [];
            foreach ($r as $i => $h) {
                $h = trim((string)$h);
                if ($h === '') { $h = 'col_' . $i; }
                if (isset($seen[$h])) { $h .= '_' . (++$seen[$h]); }  // к дубликату добавляем суффикс
                $seen[$h] = 0;
                $header[$i] = $h;
            }
            continue;
        }
        $row = [];
        foreach ($header as $i => $h) {
            $row[$h] = $r[$i] ?? null;      // недостающий столбец заполняем null
        }
        $rows[] = $row;
    }
    return $rows;
}

14.3 XLSX → CSV (потоково, подходит для больших файлов)

function xlsxToCsv(string $xlsxPath, string $csvPath, int $sheet = 0): int {
    $xlsx = SimpleXLSX::parse($xlsxPath);
    if (!$xlsx) { throw new RuntimeException(SimpleXLSX::parseError()); }

    $fp = fopen($csvPath, 'wb');
    fwrite($fp, chr(0xEF) . chr(0xBB) . chr(0xBF));   // BOM UTF-8

    $n = 0;
    foreach ($xlsx->readRows($sheet) as $r) {
        fputcsv($fp, $r);
        $n++;
    }
    fclose($fp);
    return $n;
}

function xlsxToHtml(SimpleXLSX $xlsx, int $sheet = 0, int $limit = 0): string {
    $s = '<table border="1" cellpadding="3" style="border-collapse:collapse">' . "\n";
    $y = 0;
    // внимание: у $limit в readRowsEx есть баг (см. подводный камень 1), здесь считаем сами
    foreach ($xlsx->readRowsEx($sheet) as $r) {
        if ($limit > 0 && $y >= $limit) { break; }
        $s .= '<tr>';
        foreach ($r as $c) {
            $tag = ($y === 0) ? 'th' : 'td';
            $css = sanitizeCss($c['css']);
            $v   = htmlspecialchars((string)$c['value'], ENT_QUOTES, 'UTF-8');
            $v   = preg_replace('/\R/', "<br>\n", $v);
            $s .= '<' . $tag . ' style="' . $css . '">'
                . ($v === '' ? '&nbsp;' : $v)
                . '</' . $tag . '>';
        }
        $s .= "</tr>\n";
        $y++;
    }
    return $s . '</table>';
}

14.7 Загрузка и импорт в базу данных (полный пример)

use Shuchkin\SimpleXLSX;

function importUsers(PDO $pdo, string $tmpFile): array {
    $xlsx = SimpleXLSX::parse($tmpFile);
    if (!$xlsx) {
        return ['ok' => false, 'msg' => SimpleXLSX::parseError()];
    }

    // единообразный вывод в UTC, сразу сохраняем в DATETIME
    $xlsx->setDateTimeFormat('Y-m-d H:i:s');

    $stmt = $pdo->prepare(
        'INSERT INTO users (name, phone, id_card, amount, created_at) VALUES (?,?,?,?,?)'
    );

    $ok = $fail = 0;
    $errors = [];

    $pdo->beginTransaction();
    foreach ($xlsx->readRows() as $k => $r) {
        if ($k === 0) { continue; }                     // пропускаем заголовок

        $name  = trim((string)($r[0] ?? ''));
        $phone = trim((string)($r[1] ?? ''));
        $idcard= trim((string)($r[2] ?? ''));
        $amount= is_numeric($r[3] ?? null) ? (float)$r[3] : null;
        $ctime = ($r[4] ?? '') ?: date('Y-m-d H:i:s');

        if ($name === '') { $errors[] = "Строка {$k}: имя пусто"; $fail++; continue; }

        $stmt->execute([$name, $phone, $idcard, $amount, $ctime]);
        $ok++;

        if ($ok % 500 === 0) { $pdo->commit(); $pdo->beginTransaction(); }
    }
    $pdo->commit();

    return ['ok' => true, 'imported' => $ok, 'failed' => $fail, 'errors' => array_slice($errors, 0, 20)];
}

14.8 Рекомендуемый класс-обёртка

Разом обрабатывает все описанные выше подводные камни:

<?php
use Shuchkin\SimpleXLSX;

// требуется PHP 7.4+ (используются стрелочные функции и типизированные свойства)
class XlsxReader
{
    private SimpleXLSX $xlsx;
    private string $source;
    private bool $isData;
    private int $maxRows;

    public function __construct(string $pathOrData, bool $isData = false, int $maxRows = 100000)
    {
        $this->maxRows = $maxRows;
        $this->source  = $pathOrData;
        $this->isData  = $isData;
        $x = $isData ? SimpleXLSX::parseData($pathOrData) : SimpleXLSX::parse($pathOrData);
        if (!$x) {
            throw new RuntimeException(
                'Ошибка разбора XLSX [' . SimpleXLSX::parseErrno() . ']: ' . SimpleXLSX::parseError()
            );
        }
        $this->xlsx = $x;
    }

    /** выдает построчно, автоматически пропускает полностью пустые строки, автоматически ограничивает поток */
    public function rows(int $sheet = 0): Generator
    {
        $n = 0;
        foreach ($this->xlsx->readRows($sheet) as $r) {
            if (++$n > $this->maxRows) { return; }
            if (array_filter($r, static fn($v) => $v !== '' && $v !== null) === []) {
                continue;   // пропускаем полностью пустые строки (защита от неточного dimension)
            }
            yield $r;
        }
    }

    /** ассоциативный массив с заголовком */
    public function assoc(int $sheet = 0): Generator
    {
        $header = null;
        foreach ($this->rows($sheet) as $r) {
            if ($header === null) {
                $header = array_map(
                    static fn($h, $i) => trim((string)$h) === '' ? "col_$i" : trim((string)$h),
                    $r, array_keys($r)
                );
                continue;
            }
            $row = [];
            foreach ($header as $i => $h) { $row[$h] = $r[$i] ?? null; }
            yield $row;
        }
    }

    /** ячейки со стилями, исправлены баг накопления css и безопасность href */
    public function rowsEx(int $sheet = 0): Generator
    {
        // заново parse чистый экземпляр, чтобы избежать загрязнения через css-ссылки (см. подводный камень 2)
        $ex = $this->isData ? SimpleXLSX::parseData($this->source) : SimpleXLSX::parse($this->source);
        if (!$ex) { throw new RuntimeException(SimpleXLSX::parseError()); }

        $n = 0;
        foreach ($ex->readRowsEx($sheet) as $r) {
            if (++$n > $this->maxRows) { return; }
            foreach ($r as &$c) {
                $c['css']  = $this->dedupeCss($c['css']);
                $c['href'] = $this->safeHref($c['href']);
            }
            unset($c);
            yield $r;
        }
    }

    private function dedupeCss(string $css): string
    {
        $parts = array_filter(array_map('trim', explode(';', $css)));
        return implode(';', array_unique($parts)) . ';';
    }

    private function safeHref(string $href): string
    {
        return preg_match('#^(https?://|mailto:)#i', $href) ? $href : '';
    }

    public function sheetNames(): array { return $this->xlsx->sheetNames(); }
    public function sheetsCount(): int  { return $this->xlsx->sheetsCount(); }
    public function dimension(int $s = 0): array { return $this->xlsx->dimension($s); }
}

18. Вычисление формул (XLSXFormula)

Оригинальная версия не вычисляет формулы, а только читает кэшированные значения, записанные Excel ( <v> внутри <c><f>SUM(A1:A3)</f><v>60</v></c>). Как только файл создаётся openpyxl или собственной программой, кэшированные значения пусты, и все value равны ''.

XLSXFormula — это вычислитель формул на чистом PHP, который в связке с SimpleXLSXPro позволяет получать результаты напрямую.

18.1 Базовое использование

use Shuchkin\SimpleXLSXPro;

$xlsx = SimpleXLSXPro::parse('demo.xlsx');

// 1) Вычислить конкретную ячейку
echo $xlsx->calculateCell('D6');        // 745

// 2) Вычислить произвольную формулу (не обязательно записанную в таблицу)
echo $xlsx->calculate('IF(SUM(D3:D5)>700,"отлично","средне")');   // отлично

// 3) Обойти все ячейки с формулами
foreach ($xlsx->calculatedCells(0) as $coord => $info) {
    printf("%s %s => %s\n", $coord, $info['formula'], $info['value']);
}

// 4) В rowsPro() каждая ячейка содержит поле calculated
foreach ($xlsx->readRowsPro(0) as $row) {
    foreach ($row as $c) {
        if ($c['f'] !== '') {
            echo $c['name'], ' = ', $c['calculated'], "\n";
        }
    }
}

rowsPro() также автоматически подставляет вычисленный результат, когда value пуст (отключается через $xlsx->preferCalculated = false).

18.5 Известные ограничения

  • Это не полноценный движок Excel: формулы массивов (CSE), динамические массивы (FILTER/SORT/UNIQUE), LET/LAMBDA, функции макросов не поддерживаются
  • Нераспознанные функции по умолчанию возвращают 0 ($f->lenientUnknownFunctions = false меняет на возврат #NAME?)
  • TEXT() реализует только распространённые форматы вроде 0.00 #,##0.00 0% yyyy-mm-dd; сложные пользовательские форматы деградируют
  • Даты обрабатываются по системе дат 1900 (Excel for Windows); для книг date1904 пересчёт не выполняется
  • Циклические ссылки возвращают #CIRC!, итеративное решение, как в Excel, не выполняется

Вид ячейки в XML

<!-- Общая строка -->
<c r="A1" t="s"><v>0</v></c>

<!-- Число -->
<c r="B2" s="1"><v>1233.34</v></c>

<!-- Логическое значение -->
<c r="C3" t="b"><v>1</v></c>

<!-- Формула (с кэшированным значением) -->
<c r="D4" s="2"><f>B3*2</f><v>2466.68</v></c>

<!-- Значение ошибки -->
<c r="E5" t="e"><v>#DIV/0!</v></c>

<!-- Встроенная строка -->
<c r="F6" t="inlineStr"><is><t>текст</t></is></c>

Соответствие (как это видит SimpleXLSX)

XML SimpleXLSX
r в <c r="B2"> name в rowsEx()
t в <c t="s"> type в rowsEx()
<v> или sharedStrings value в rowsEx()
s в <c s="3"> s в rowsEx() → cellFormats[3]
<f> f в rowsEx()
<col width hidden> width / hidden в rowsEx()
<row ht customHeight hidden> height / hidden в rowsEx()
<hyperlink ref id> + rels href в rowsEx()
<comment ref> comment в rowsEx()
numFmts из styles.xml $xlsx->nf / cellFormats[n]['format']

Вместо заключения

Ценность SimpleXLSX — в своевременной достаточности: он доводит задачу «чтения Excel» до 80 баллов, платой за это являются ноль зависимостей и возможность начать с одного rows(). Оставшиеся 20 баллов (вычисление формул, диаграммы, точная вёрстка), если они вам нужны, — значит пора переходить на PhpSpreadsheet, но в большинстве сценариев импорта он вам не понадобится.

Три пункта, где при использовании чаще всего случаются проблемы, повторим ещё раз:

  1. Числовой формат: ведущие нули, номера удостоверений личности, длинные числа — обязательно задавайте как текст прямо в источнике Excel;
  2. Формулы: отсутствие значения — обычное дело, библиотека не вычисляет формулы;
  3. Безопасность: перед рендерингом загруженных пользователями xlsx href обязательно фильтруйте самостоятельно, а версия должна быть >= 1.1.19.
