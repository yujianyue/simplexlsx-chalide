SimpleXLSX 中文开发文档

面向 PHP 开发者的 shuchkin/simplexlsx 完整中文说明书与开发指南 基于源码逐行通读 + PHP 8.3 实测验证编写（版本 1.1.19）

一、这是什么

SimpleXLSX 是一个纯 PHP 的 xlsx 读取器，用于解析 Microsoft Excel 2007+ 的 .xlsx 工作簿并把单元格数据取成 PHP 数组。

它的核心卖点只有一句话：不依赖任何额外 PHP 扩展，只用内置的 SimpleXML + zlib 就能读 Excel。

它做了什么

能力 说明
读取单元格值 文本、数字、布尔、日期、错误值、富文本
多工作表 索引/名称访问、隐藏表识别、激活表识别
样式提取 字体、颜色、填充、边框、对齐、行高列宽
超链接与批注 单元格外链、内部跳转、批注纯文本
流式读取 生成器 readRows()，适合大文件
HTML 导出 toHTML() / toHTMLEx() 一键转表格
零扩展依赖 无 php-zip、无 php-excel，纯 PHP 实现解压

它不能做什么

这一点比"能做什么"更重要，先说清楚能省掉你半天时间：

不在能力范围内 原因
写入/生成 xlsx 只读库。写请用配套的 SimpleXLSXGen
读取老格式 .xls 完全不同的二进制格式，请用 SimpleXLS
计算公式 只返回 Excel 保存时缓存的结果值，不重算公式
合并单元格信息 不解析 mergeCells，合并区只有左上角有值
图片/图表/透视表 全部忽略
条件格式、数据验证 不解析
单元格"原始富文本分段" 富文本会被拼接成一个字符串（见 parseRichText）
读 .xlsb / 加密文件 二进制格式与加密 ZIP 都不支持

一句话选型：如果你的需求是"用户上传一个 Excel，我把里面的表格读出来存数据库"，SimpleXLSX 是性价比最高的选择（几十 KB、无依赖、够快）。如果你需要"生成带图表的复杂报表"或"精确还原打印样式"，请上 PhpSpreadsheet。

二、环境要求与安装

2.1 系统要求

要求 说明
PHP >= 5.5（实测 PHP 8.3 正常；PHP 5.5+ 用 Generator 兼容写法）
ext-simplexml 必需，解析 XML
ext-zlib 必需，gzinflate() 解压 ZIP 条目
ext-libxml 必需
ext-mbstring 必需（composer 声明），用于 func_overload 兼容分支

注意：不需要 ext-zip。ZIP 解包是作者自己手写的（见 unzip() 方法）。这是它能在各种廉价虚拟主机上跑起来的原因。

2.2 安装方式一：Composer（推荐）

composer require shuchkin/simplexlsx

然后：

require_once 'vendor/autoload.php';

use Shuchkin\SimpleXLSX;

if ( $xlsx = SimpleXLSX::parse('book.xlsx') ) {
    print_r( $xlsx->rows() );
} else {
    echo SimpleXLSX::parseError();
}

⚠️ 注意：composer.json 的 autoload 里只注册了 src/SimpleXLSX.php： json "autoload": { "classmap": ["src/SimpleXLSX.php"] } SimpleXLSXEx.php 没有被注册进 classmap，它是通过 require_once __DIR__.'/SimpleXLSXEx.php' 在调用 readRowsEx() 时手动加载的。你不用管，但也别指望 class_exists('Shuchkin\SimpleXLSXEx') 在没调用过 rowsEx() 时为 true。

2.3 安装方式二：单文件直接引入

适合不能装 Composer 的环境：

require_once __DIR__ . '/src/SimpleXLSX.php';

use Shuchkin\SimpleXLSX;

SimpleXLSX.php 是自包含的，不依赖其他文件（除非你要用 rowsEx()）。

2.4 在框架中使用

Laravel：composer 装好后直接用，无需 ServiceProvider。

use Shuchkin\SimpleXLSX;

public function import(Request $request) {
    $request->validate(['file' => 'required|file|mimes:xlsx|max:10240']);
    $xlsx = SimpleXLSX::parse($request->file('file')->getRealPath());
    // ...
}

ThinkPHP / 其他：require 文件路径或 composer autoload 均可。

3.2 三种打开方式

// ① 从文件路径（最常用）
$xlsx = SimpleXLSX::parse('/path/to/book.xlsx');
$xlsx = SimpleXLSX::parseFile('/path/to/book.xlsx');   // 等价写法

// ② 从内存中的二进制数据
$data = file_get_contents('https://example.com/book.xlsx');
// 或者从数据库 BLOB、Redis 缓存里取出
$xlsx = SimpleXLSX::parseData($data);

// ③ 也支持直接给 URL（内部走 file_get_contents，受 allow_url_fopen 限制）
$xlsx = SimpleXLSX::parse('https://www.example.com/example.xlsx');

三者关系（源码真相）：

public static function parse($filename, $is_data = false, $debug = false) // 核心
public static function parseFile($filename, $debug = false)  // → parse($filename, false, $debug)
public static function parseData($data, $debug = false)      // → parse($data, true, $debug)

parse() 内部先 unzip() 再 parseEntries()，成功返回 SimpleXLSX 对象，失败返回 false。

3.3 经典 OOP 写法

如果你更喜欢"构造对象 + 检查状态"，而不是"静态工厂 + 判 false"：

$xlsx = new SimpleXLSX('books.xlsx');
if ( $xlsx->success() ) {
    foreach ( $xlsx->rows() as $r ) {
        // ...
    }
} else {
    echo 'xlsx error: ' . $xlsx->error();
}

构造函数签名：__construct($filename = null, $is_data = null, $debug = null)。

两种写法的差异：静态 parse() 失败返回 false 并把错误信息塞进静态变量；new 方式永远返回对象，用 success() 判断。底层都调用同一个 unzip()。

3.4 调试模式

ini_set('error_reporting', E_ALL);
ini_set('display_errors', 1);

if ( $xlsx = SimpleXLSX::parseFile('books.xlsx', true) ) {
    echo $xlsx->toHTML();
} else {
    echo SimpleXLSX::parseError();
}

开启 $debug = true 后，内部每次 error() 都会额外 trigger_error(..., E_USER_WARNING)，方便定位。

四、核心概念：xlsx 是怎么被读出来的

要真正用好这个库（尤其是排查问题），值得花 3 分钟理解它的工作流。

4.1 xlsx 本质是一个 ZIP

.xlsx 就是一个改了后缀的 ZIP 包，里面是一堆 XML：

book.xlsx
├── _rels/.rels                        ← 入口，指明 workbook 在哪
├── xl/
│   ├── workbook.xml                   ← 工作表清单、名称、顺序、激活表
│   ├── _rels/workbook.xml.rels        ← rId → 实际文件的映射
│   ├── sharedStrings.xml              ← 共享字符串池
│   ├── styles.xml                     ← 字体/填充/边框/数字格式
│   ├── theme/theme1.xml               ← 主题色
│   └── worksheets/
│       ├── sheet1.xml                 ← 真正的单元格数据
│       ├── _rels/sheet1.xml.rels      ← 该表的超链接/批注
│       └── ...

4.2 解析流程（对应源码方法）

SimpleXLSX::parse($file)
    │
    ├─ unzip($filename, $is_data)      ← 手写 ZIP 解包，全部条目读入 $this->package['entries']
    │                                     （此时不解压，只保存压缩数据 + 头信息）
    │
    └─ parseEntries()                  ← 建立索引
         ├─ 读 _rels/.rels → 找到 officeDocument → xl/workbook.xml
         ├─ 遍历 workbook.xml 的 <sheet> → $this->sheetMetaData[i]（name/sheetId/state/id）
         ├─ 读 xl/_rels/workbook.xml.rels → 按 rId 分派：
         │     worksheet    → $this->sheets[i] = SimpleXMLElement（并记 sheetFiles[i]）
         │     sharedStrings→ $this->sharedstrings[] = 字符串数组
         │     styles       → $this->styles + $this->nf + $this->cellFormats
         │     theme        → $this->theme
         └─ 从 workbook.xml 的 <bookViews><workbookView activeTab="N"> 取 $this->activeSheet

4.3 内存模型（重点）

这一点很多人会踩坑：

  1. unzip() 一次性 file_get_contents() 整个文件到内存；
  2. 所有 ZIP 条目（压缩态）全部保留在 $this->package['entries'] 数组里；
  3. 调用 getEntryXML($name) 时才 gzinflate() 解压，解压完立刻 deleteEntry() 从数组中删掉（省内存）；
  4. 但 sheet1.xml 被 simplexml_load_string() 解析成 SimpleXMLElement 后常驻内存。

结论：峰值内存至少是文件大小的 2~3 倍，再加上 XML 对象树。readRows() 只能省掉"结果数组"那一层，省不掉"整表 DOM"这一层。详见 第十章。

4.4 单元格坐标

  • A1 风格（Excel 表示法）与 [列索引, 行索引]（0-based）互相转换：
  • getIndex('AB12') → [27, 11]（实测）
  • SimpleXLSX::num2name(3) → 'C'
  • num2name(1) = 'A'，num2name(27) = 'AA'（实测）

五、API 全量参考

以下签名全部来自对 1.1.19 源码的反射提取，参数默认值与源码完全一致。

5.1 静态工厂方法

SimpleXLSX::parse($filename, $is_data = false, $debug = false)

参数 类型 说明
$filename string 文件路径、URL，或当 $is_data=true 时为 xlsx 二进制内容
$is_data bool true 表示第一参数是数据而非路径
$debug bool 开启后错误会 trigger_error

返回：成功 SimpleXLSX 对象，失败 false。

$xlsx = SimpleXLSX::parse('book.xlsx');          // 文件
$xlsx = SimpleXLSX::parse($binary, true);        // 内存数据
$xlsx = SimpleXLSX::parse('a.xlsx', false, true);// 调试

SimpleXLSX::parseFile($filename, $debug = false)

等价于 parse($filename, false, $debug)。语义更清晰，推荐。

SimpleXLSX::parseData($data, $debug = false)

等价于 parse($data, true, $debug)。用于数据库 BLOB / 缓存 / 网络流。

SimpleXLSX::parseError($set = false) / SimpleXLSX::parseErrno($set = false)

读取（或设置）最近一次 parse() 的错误信息/错误码。

if ( !$xlsx = SimpleXLSX::parse('x.xlsx') ) {
    echo SimpleXLSX::parseErrno() . ': ' . SimpleXLSX::parseError();
}

⚠️ 这两个方法用的是 static 局部变量，是全局共享状态。连续解析多个文件时，务必在每次 parse() 后立刻读取，否则会被后一次解析覆盖。

5.2 状态与错误

方法 返回 说明
success() bool 是否解析成功（内部就是 !$this->error）
errno() int 实例级错误码
error($num = null, $str = null) string|false 读/写错误信息
getPackage() array 原始 ZIP 包信息（filename/mtime/size/entries） 
$xlsx = new SimpleXLSX('books.xlsx');
if ( $xlsx->success() ) {
    // ...
} else {
    echo $xlsx->errno() . ' - ' . $xlsx->error();
}

5.3 工作表元数据

方法 返回 说明
sheetsCount() int 工作表数量
sheetNames() array [0 => 'Sheet1', 1 => 'Sheet2', ...]
sheetName($i) string|false 按索引取名称
sheetMeta($i = null) array|false 单个表的全部属性；传 null 返回全部
isHiddenSheet($i) bool 是否隐藏工作表
getSheets() array 返回 SimpleXMLElement[] 原始工作表对象
worksheet($i = 0) SimpleXMLElement|false 取单个表的原始 XML 对象
$xlsx->activeSheet int 属性，Excel 最后保存时激活的表索引（0-based）

实测输出：

$x = SimpleXLSX::parse('types.xlsx');
print_r($x->sheetNames());
// Array( [0] => 类型测试 [1] => 第二页 [2] => 隐藏页 )

print_r($x->sheetMeta());
// Array(
//   [0] => Array( [name] => 类型测试 [sheetId] => 1 [state] => visible [id] => rId1 )
//   [1] => Array( [name] => 第二页   [sheetId] => 2 [state] => visible [id] => rId2 )
//   [2] => Array( [name] => 隐藏页   [sheetId] => 3 [state] => hidden  [id] => rId3 )
// )

var_dump($x->isHiddenSheet(2)); // true

按名字找索引（库没提供，自己写）：

function sheetIndexByName(SimpleXLSX $xlsx, string $name): ?int {
    $map = array_flip($xlsx->sheetNames());
    return $map[$name] ?? null;
}

💡 sheets 数组的键是按 workbook.xml 中 <sheet> 出现顺序排的，并且 parseEntries() 结尾做了 ksort()，所以索引稳定对应 Excel 里从左到右的标签顺序。

5.4 读取数据（核心）

rows($worksheetIndex = 0, $limit = 0): array

最常用方法。返回二维数组，每行是从第 0 列开始的数值索引数组。

参数 说明
$worksheetIndex 工作表索引，0-based
$limit 最多返回几行；0 表示不限 
foreach ( $xlsx->rows() as $r ) {
    echo $r[0] . ' | ' . $r[1] . "\n";
}

内部实现：iterator_to_array($this->readRows(...), false)，即一次性全部展开成数组。

空行补齐行为：readRows() 会按 dimension() 的行数补齐尾部空行。也就是说如果 Excel 的 <dimension> 声明了 100 行但只有 3 行有数据，你会拿到 100 行（后 97 行全是空字符串数组）。

readRows($worksheetIndex = 0, $limit = 0): Generator

与 rows() 返回同样的数据，但是生成器，逐行产出，不占用结果数组内存。

foreach ( $xlsx->readRows() as $k => $r ) {
    fputcsv($fp, $r);
}

rowsEx($worksheetIndex = 0, $limit = 0): array

类型判定逻辑（源码要点）

// 1) 类型为空或 n 时，靠样式里的数字格式串判定是不是日期
if ($dataType === '' || $dataType === 'n') {
    $s = (int)$cell['s'];
    if ($s > 0 && isset($this->cellFormats[$s])) {
        if (array_key_exists('format', $this->cellFormats[$s])) {
            $format = $this->cellFormats[$s]['format'];
            // 去掉引号内的字面量后，格式串里含 m（月/分）就当日期
            if ($format && preg_match('/[mM]/', preg_replace('/"[^"]+"/', '', $format))) {
                $dataType = 'D';
            }
        }
    }
}

// 2) 默认分支：字符串，能转数字就转
$value = (string)$cell->v;
if (is_numeric($value)) {
    if ($value == (int)$value)   $value = (int)$value;
    elseif ($value == (float)$value) $value = (float)$value;
}

这意味着：

  1. 日期判定靠"格式码里有没有字母 m"。一张表里如果数字列被误设成含 m 的自定义格式，会被错误地转成日期。反之，日期列如果被设成 General，会返回 Excel 序列号浮点数（如 44613.0）而不是日期。
  2. 前导零会丢失。像 007（当成数字）会变成 7。手机号、身份证号、邮政编码在 Excel 里必须设为文本格式，否则 SimpleXLSX 会返回 int/float。这是导入系统的头号数据事故来源。
  3. 大整数精度：超过 PHP int 范围或带小数时会转 float，1234567890123456789 可能变成 1.2345678901235E+18。

关于"纯时间"

Excel 里不带日期的时间（如 13:41:00）存储值是 0.570138...（整数部分为 0）。unixstamp() 对 d == 0 走的是特殊分支：

$t = (abs($d) > 0) ? ($d - 25569) * 86400 + round($t * 86400) : round($t * 86400);

结果是以 Unix epoch（1970-01-01）为基准，所以 13:41 → '1970-01-01 13:41:00'（实测确认）。

业务上处理办法：只取时间部分。

$val = $cell['value'];               // '1970-01-01 13:41:00'
$time = substr($val, 11);            // '13:41:00'

关于公式

SimpleXLSX 不计算公式，它读的是 Excel 保存进文件的缓存结果（<c><f>B3*2</f><v>1236</v></c> 里的 <v>）。

实测发现：用 openpyxl / 部分非 Excel 工具生成的 xlsx 不写缓存值，此时 value 是空字符串，只有 f 有内容。

处理建议：

foreach ($xlsx->rowsEx() as $row) {
    foreach ($row as $c) {
        $v = $c['value'];
        if ($v === '' && $c['f'] !== '') {
            // 无缓存值的公式单元格
            $v = null; // 或标记待人工处理 / 自己重算
        }
    }
}

八、日期与时间专题

8.1 Excel 日期的本质

Excel 日期是一个浮点数：整数部分是"自 1899-12-30 起的天数"（1900 系统），小数部分是一天中的时间比例。例如 42472.570138889 = 2016-04-12 13:41:00。

为什么是 1899-12-30 而不是 1900-01-01？因为 Excel 有个著名的"1900 年是闰年"bug。unixstamp() 里的 25569 就是 1899-12-30 到 1970-01-01 的天数差。

8.2 转换公式

public function unixstamp($excelDateTime) {
    $d = floor($excelDateTime);      // 天数
    $t = $excelDateTime - $d;        // 当天时间比例
    if ($this->date1904) { $d += 1462; }   // 1904 系统补 1462 天
    $t = (abs($d) > 0) ? ($d - 25569) * 86400 + round($t * 86400) : round($t * 86400);
    return (int)$t;
}

然后用 gmdate($this->datetimeFormat, $ts) 格式化 —— 注意是 gmdate() 不是 date()，即按 UTC 解释时间戳。

8.3 四种用法

$xlsx = SimpleXLSX::parse('book.xlsx');

// ① 默认：ISO 格式（可直接存 MySQL DATETIME）
echo $xlsx->getCell(0, 'C2');   // 2016-04-12 13:41:00

// ② 自定义格式
$xlsx->setDateTimeFormat('d.m.Y H:i');
echo $xlsx->getCell(0, 'C2');   // 12.04.2016 13:41

// ③ Unix 时间戳
$xlsx->setDateTimeFormat('U');
$ts = $xlsx->getCell(0, 'C2');  // 1645401600（字符串）
echo gmdate('Y-m-d', $ts);      // 2016-04-12

// ④ 原始 Excel 序列号（放弃自动转换）
$xlsx->setDateTimeFormat(null);
$xd = $xlsx->getCell(0, 'C2');  // 42472.570138889（float）
echo gmdate('m/d/Y', $xlsx->unixstamp($xd));  // 04/12/2016

实测确认（同一单元格，四种设置）：

NULL             => 44613.0                      (float)
'Y-m-d H:i:s'    => '2022-02-21 00:00:00'        (string)
'd.m.Y H:i'      => '21.02.2022 00:00'           (string)
'U'              => '1645401600'                 (string)

注意 'U' 返回的是字符串不是整数，需要 (int) 转换。

8.4 时区陷阱

gmdate() 意味着：Excel 里写的 2016-04-12 13:41，取出来就是 2016-04-12 13:41:00，不会因为服务器时区而偏移。这通常正是你想要的（Excel 里看到什么就是什么）。

反过来说，如果你需要按某个时区解释，需要自己加偏移：

$xlsx->setDateTimeFormat('U');
$ts = (int)$xlsx->getCell(0, 'C2');
$local = date('Y-m-d H:i:s', $ts + 8 * 3600);  // 按东八区显示

8.5 1904 日期系统

Mac 版 Excel 老文件可能用 1904 系统。库会自动从 workbook.xml 的 <workbookPr date1904="1"> 检测并设置 $xlsx->date1904 = 1。

需要手动干预时（属性是 public）：

$xlsx->date1904 = 1;   // 强制用 1904 系统

如果你发现所有日期都比实际晚 4 年零 1 天，就是这个问题。

8.6 日期列识别工具函数

rows() 只给你值，不告诉你哪一列是日期。用 rowsEx() 的 format 判断：

function isDateCell(array $cell): bool {
    if ($cell['type'] === 'd') return true;
    if (!in_array($cell['type'], ['', 'n'], true)) return false;
    $fmt = preg_replace('/"[^"]+"/', '', $cell['format']);
    // 含 y/m/d/h/s 中任一且不是纯数字格式
    return (bool)preg_match('/[ymdhs]/i', $fmt);
}

9.5 字号换算

$css .= 'font-size: ' . (round($cf['f-size'] * 1.3333) + 2) . 'px;';

Excel 字号单位是磅（pt），这里粗略按 pt × 1.3333 + 2 转 px（1pt ≈ 1.333px）。所以 11 号字 → 17px，14 号 → 21px。

也就是说：medium、thick、double、hair 在 HTML 里长得一样。这是有意的简化，别指望像素级还原。

9.7 自己生成 CSS（绕过内置 css 的 bug）

如果内置的 css 字段不够用（见第十三章的累加 bug），可以直接读 cellFormats 自己拼：

function buildCss(SimpleXLSX $xlsx, int $s): string {
    $f = $xlsx->cellFormats[$s] ?? [];
    $css = '';
    if (!empty($f['color']))    $css .= 'color:#' . $f['color'] . ';';
    if (!empty($f['bgcolor']))  $css .= 'background-color:#' . $f['bgcolor'] . ';';
    if (!empty($f['f-b']))      $css .= 'font-weight:bold;';
    if (!empty($f['f-i']))      $css .= 'font-style:italic;';
    if (!empty($f['align']))    $css .= 'text-align:' . $f['align'] . ';';
    if (!empty($f['valign']))   $css .= 'vertical-align:' . $f['valign'] . ';';
    if (!empty($f['f-size']))   $css .= 'font-size:' . (round($f['f-size'] * 1.3333) + 2) . 'px;';
    return $css;
}

十、大文件与内存优化

10.1 官方基准数据

CHANGELOG 1.0.12 里作者给出的实测：

方式 10 万行内存占用
rowsEx() ~880 MB
readRowsEx() ~162 MB

差了 5 倍多。原因就是 rows() / rowsEx() 会把整张表展开成一个巨大的 PHP 二维数组（PHP 数组的每个元素开销约 80~100 字节，10 万 × 10 列就是 100 万个 zval）。

10.2 内存去哪了

总内存 ≈ 文件大小（原始二进制）
       + 所有 ZIP 条目压缩数据（package['entries']）
       + 已解析工作表的 SimpleXMLElement 树（最大头）
       + 共享字符串数组
       + 结果数组（rows/rowsEx 才有）

readRows() 只能砍掉最后一项。

10.3 优化清单

① 优先用生成器

// ❌ 差：整表进内存
foreach ($xlsx->rows() as $r) { ... }

// ✅ 好：逐行产出
foreach ($xlsx->readRows() as $r) { ... }

② 流式写入目标，不要累积

$f = fopen('out.csv', 'wb');
fwrite($f, chr(0xEF) . chr(0xBB) . chr(0xBF));  // UTF-8 BOM，Excel 打开中文不乱码
foreach ($xlsx->readRows() as $r) {
    fputcsv($f, $r);
}
fclose($f);

③ 分批处理并释放

$pdo->beginTransaction();
$stmt = $pdo->prepare('INSERT INTO t (a,b,c) VALUES (?,?,?)');
$i = 0;
foreach ($xlsx->readRows() as $k => $r) {
    if ($k === 0) continue;                 // 跳过表头
    $stmt->execute([$r[0], $r[1], $r[2]]);
    if (++$i % 1000 === 0) {
        $pdo->commit(); $pdo->beginTransaction();
    }
}
$pdo->commit();

④ 调高内存上限（最后手段）

ini_set('memory_limit', '512M');

⑤ 超大表的现实建议

如果一个 xlsx 超过 20~30 MB 或 50 万行，SimpleXLSX 不是合适的工具。因为 XML DOM 必须整个驻留内存。这种情况应该：

  • 在上传环节让用户改传 CSV；
  • 或用流式 SAX 解析器（如 XMLReader + expand()）自己写；
  • 或用 PhpSpreadsheet 的 setReadDataOnly(true) + chunk 读取（也吃内存，但稍好）。

10.4 $limit 参数（⚠️ 各方法行为不一致）

rows() / readRows() / rowsEx() / readRowsEx() 都声明了 $limit，但实测只有前三个可靠：

$xlsx->readRows(0, 100);    // ✅ 正常
$xlsx->rowsEx(0, 100);      // ✅ 正常（内部走 iterator_to_array）
$xlsx->readRowsEx(0, 100);  // ❌ 失效，返回全部行

readRows() 实测边界行为（表共 13 行）：

$limit 返回行数
0 13（不限）
1 1
2 2
99 13

同样条件下 readRowsEx() 无论传 1/2/3/5 都返回 13 行。原因与规避见坑 1。

⚠️ toHTML() 和 toHTMLEx() 根本没有 $limit 参数（源码只有 1 个参数）。

十一、错误处理与错误码

11.1 主错误码表（$xlsx->errno() / SimpleXLSX::parseErrno()）

码 消息 含义 排查方向
1 File not found <path> 文件不存在或不可读 路径、is_readable()、权限、上传临时文件已被回收
2 Unknown archive format 不是合法 ZIP 文件损坏、实际是 .xls 伪装成 .xlsx、下载不完整、是 HTML 错误页
3 XML-entry <name> parser error ... 包内 XML 解析失败 文件损坏；或 XML 里有 libxml 不支持的内容
4 XML-entry not found <name> 需要的 XML 条目没读到 ZIP 结构异常；条目解压/CRC 失败也会落到这个码
5 Entry not found <name> 包内找不到指定文件 非标准生成器的 xlsx

11.2 各错误实测复现

11.3 隐藏的内部错误（不通过 errno 暴露）

getEntryData() 里有一套条目级错误码，但它们只写进 $entry['error'] 并让方法返回 false，不会调用 $this->error()。于是上层 getEntryXML() 统一报 errno=4。

内部码 含义
2 Decompression of data failed（解压失败）
3 Uncompressed size mismatch（大小不符）
4 CRC32 checksum mismatch（校验和错）
6 不支持的压缩方式 / ZIP64 条目过大
7 PHP BZIP2 扩展不可用

排查含义：如果你拿到 errno=4 "XML-entry not found" 但文件明明能被 Excel 打开，大概率是 CRC/解压问题（文件在传输中损坏），或者是 BZIP2 压缩的 ZIP（极罕见）。可以临时打印 $xlsx->getPackage()['entries'] 看每个条目的 error 字段。

十二、安全注意事项

12.1 XSS：值已转义，但 href 没有

好消息：toHTML() 和 toHTMLEx() 对单元格值都做了 htmlspecialchars($v, ENT_QUOTES)。

坏消息：rowsEx() 返回的 href 字段没有任何协议校验。如果你自己拼 HTML：

// ❌ 危险：href 可能是 javascript:alert(1)
echo '<a href="' . $cell['href'] . '">link</a>';

// ✅ 正确：白名单校验
function safeHref(string $href): string {
    if (preg_match('#^https?://#i', $href)) return $href;
    if (preg_match('#^mailto:#i', $href))   return $href;
    if (preg_match('/^[^!]+![A-Z]+\d+$/', $href)) return ''; // 内部跳转，HTML 里无法表达
    return '';
}
echo '<a href="' . safeHref($cell['href']) . '">link</a>';

12.2 CSS 注入（CVE-2024-55878）

历史版本存在通过样式注入 CSS 的漏洞（GHSA-x6mh-rjwm-8ph7）。1.1.19 已修，做法：

  • 字体名强制白名单：preg_match('/^[a-zA-Z0-9 ]+$/', $name)，不合法就回退 Calibri
  • 颜色强制 6 位 hex：preg_match('/^[A-F0-9]{6}$/', $c)
  • 对齐值只从固定映射表取

但如果你把 css 字段直接内联到 style=""，仍建议二次净化（尤其面向公网渲染用户上传文件时）：

// 粗过滤：只保留已知安全的 CSS 属性
function sanitizeCss(string $css): string {
    $out = '';
    foreach (explode(';', $css) as $decl) {
        $decl = trim($decl);
        if (preg_match('/^(color|background-color|font-family|font-size|font-weight|font-style|text-decoration|text-align|vertical-align|border-(top|right|bottom|left)-(style|color|width)):/', $decl)) {
            $out .= $decl . ';';
        }
    }
    return $out;
}

更彻底的方案：接 HTMLPurifier。

12.3 XXE（XML 外部实体）

源码已处理：

if (LIBXML_VERSION < 20900 && function_exists('libxml_disable_entity_loader')) {
    $_old = libxml_disable_entity_loader();
}
$entry_xmlobj = simplexml_load_string($entry_xml, 'SimpleXMLElement', LIBXML_COMPACT | LIBXML_PARSEHUGE);

libxml >= 2.9 默认不加载外部实体，无需手动禁用。前提是你要用较新的 libxml，别在 CentOS 6 这种老系统上裸跑。

12.4 解压炸弹（Zip Bomb）

xlsx 是 ZIP，理论上存在 zip bomb 风险（1KB 文件解压出 10GB）。SimpleXLSX 没有做解压大小限制。

防护：在上传前限制文件大小（如 ≤ 10 MB），并在 PHP 侧设 memory_limit 兜底。

12.5 其他

  • 不要信任 dimension：恶意文件可以声明 A1:XFD1048576，导致 readRows() 尝试补齐上亿个空行。建议自己加行数上限。
  • 文件名：不要用上传的原始文件名拼路径（路径穿越），自己生成文件名。
  • 临时文件生命周期：PHP 会在脚本结束后删除上传临时文件，务必先 move_uploaded_file()。

十三、已知问题与避坑清单

以下是我通读源码 + 实测发现的行为，官方文档没有记载，按严重程度分组（🔴 高危 / 🟠 中 / 🟢 低）。

🔴 坑 1：readRowsEx() 的 $limit 参数失效（1.1.19 实测确认）

现象：当 $limit 小于工作表行数时，readRowsEx() 无视 limit，返回满行数（多出来的全是空行）。

实测数据（工作表共 13 行）：

$limit readRows() 返回 readRowsEx() 返回
0（不限） 13 13
1 1 ✅ 13 ❌
2 2 ✅ 13 ❌
3 3 ✅ 13 ❌
5 5 ✅ 13 ❌
13 13 ✅ 13 ✅
20 13 ✅ 13 ✅

根因：SimpleXLSXEx::readRowsEx() 里命中 limit 时用的是 break，而 SimpleXLSX::readRows() 用的是 return：

// SimpleXLSX::readRows() —— 正确
yield $r;
$_limit--;
if ($_limit === 0) { return; }        // ← 直接结束生成器

// SimpleXLSXEx::readRowsEx() —— bug
yield $cells;
$_limit--;
if ($_limit === 0) { break; }         // ← 只跳出 foreach
// ...
while ($curR < $numRows) {            // ← break 后仍会进入这里
    yield $emptyRow;                  //    继续补空行，且 $_limit 已变负数，永远不会再命中 0
    $_limit--;
    if ($_limit === 0) { return; }
}

影响：用 rowsEx(0, 100) 想"预览前 100 行"时，实际会拿到整张表的全部行（后面临时补的空行），大文件下内存和耗时都失控。

规避：自己计数中断，别依赖 $limit：

$n = 0;
foreach ($xlsx->readRowsEx(0) as $r) {      // 不传 limit
    if (++$n > 100) break;
    // ...
}

✅ 已修复：本文档配套的补丁（见 十七、源码 BUG 修复清单）把 break 改成了 return，修复后 readRowsEx() 的 $limit 与 readRows() 行为一致，$limit 可以直接用了。

🔴 坑 2：同一实例多次调用 rowsEx() 会让 CSS 无限累加

现象（实测）：

第1次 rowsEx B3.css = 'color: #000000;font-family: Calibri;font-size: 17px;text-align: right;×4'
第2次 rowsEx B3.css = '... text-align: right;×8'
第3次 rowsEx B3.css = '... text-align: right;×12'

原因：SimpleXLSXEx::valueEx() 里是引用赋值：

$r['css'] = &$this->css[$r['s']];           // 引用！
if (...) { $r['css'] .= 'text-align: right;'; }  // 写进了 $this->css[$s] 本身

每次调用 rowsEx()/toHTMLEx()，所有"非空且无对齐且非文本类型"的单元格都会往同一个共享字符串再追加一次。

影响：输出 HTML 变长、样式表污染（虽然 CSS 语义上重复声明无害，但字符串会翻倍增长）。

规避：

// 方案 A：每次重新 parse（最简单）
$xlsx1 = SimpleXLSX::parse($f); $a = $xlsx1->rowsEx();
$xlsx2 = SimpleXLSX::parse($f); $b = $xlsx2->rowsEx();

// 方案 B：去重
$css = implode(';', array_unique(array_filter(explode(';', $cell['css'])))) . ';';

// 方案 C：不用内置 css，自己按 cellFormats 生成（见 9.7）

✅ 已修复：配套补丁把引用赋值改成了值拷贝（$r['css'] = isset($this->css[$r['s']]) ? ... : ''），同一实例反复调用不再累加。

🔴 坑 2：toHTML() / toHTMLEx() 没有 $limit 参数

README 写的签名是 toHTML($worksheetIndex = 0, $limit = 0)，但源码反射实测只有 1 个参数。传第二个参数静默失效。

需要限制行数：

echo '<table>';
$i = 0;
foreach ($xlsx->readRowsEx(0, 100) as $r) {   // 用生成器 + limit
    echo '<tr>';
    foreach ($r as $c) { echo '<td>' . htmlspecialchars($c['value']) . '</td>'; }
    echo '</tr>';
}
echo '</table>';

✅ 已修复：配套补丁给两个方法补上了 $limit 参数并传给 readRows()/readRowsEx()，现在可以直接 toHTML(0, 100)。

🟠 坑 3：公式单元格可能返回空字符串

不计算公式，只读缓存值。非 Excel 生成的 xlsx 常常没有缓存值 → value === ''。详见 第七章。

✅ 已解决：配套扩展 SimpleXLSXPro 自带公式计算引擎，无缓存值的公式也能算出结果，详见 十八、公式计算。

🟠 坑 4：前导零 / 长数字精度丢失

Excel 里存成数字的 007、130123199001011234 会被转成 int/float，前导零和精度都没了。

必须从源头解决：要求用户把这些列在 Excel 里设为"文本"格式，或导入后按业务规则补零：

$id = str_pad((string)$v, 18, '0', STR_PAD_LEFT);

🟠 坑 5：dimension 不准导致多余空行

readRows() 在遍历完真实行之后，还会 while ($curR < $numRows) yield $emptyRow;。如果 XML 里 dimension 声明的行数远大于实际，你会收到一堆全空行。

防御：

$maxRows = 100000;
$n = 0;
foreach ($xlsx->readRows() as $r) {
    if (++$n > $maxRows) break;
    if (array_filter($r) === []) continue;   // 跳过全空行
    // ...
}

🟡 坑 6：getCell() 极慢

内部是 XPath 全表扫描。源码注释明写 VERY SLOW!。取 1000 个单元格用 getCell() 会有明显卡顿。批量取值请用 rows() 后按索引访问。

🟡 坑 7：parseError() 是全局静态状态

static $error = false;
return $set ? $error = $set : $error;

多文件循环解析时，如果中间某次成功，parseError() 不会被清空（成功路径不调用 parseError()）。所以：

// ❌ 第二次 parse 成功后，读到的还是第一次的错误
SimpleXLSX::parse('bad.xlsx');   // 失败，设置 error
SimpleXLSX::parse('good.xlsx');  // 成功，不重置 error
echo SimpleXLSX::parseError();   // 仍然显示 bad.xlsx 的错误！

// ✅ 正确：只在失败分支里读
if (!$x = SimpleXLSX::parse('bad.xlsx')) { echo SimpleXLSX::parseError(); }
if (!$x = SimpleXLSX::parse('good.xlsx')) { echo SimpleXLSX::parseError(); }

✅ 已修复：配套补丁给 parseError()/parseErrno() 增加了 $reset 参数，并在 parse() 成功分支里主动清零。修复后实测： SimpleXLSX::parse('bad.xlsx') → 失败后 parseError() = 'File not found bad.xlsx'；紧接着 parse('good.xlsx') 成功 → parseError() = false。

或者在循环里用 new SimpleXLSX() + $xlsx->error() 实例方法，天然隔离。

🟡 坑 8：工作表不存在时 rows() 返回空数组而不报错

var_dump($xlsx->rows(9));   // array(0) {} —— 空数组，不是 false
echo $xlsx->errno();        // 但 errno 被设成了 6

所以判断成功不能只看 empty($rows)，要查 errno() 或先查 sheetsCount()。

🟡 坑 9：样式索引越界会有 PHP Notice

valueEx() 里：

$st = &$this->xlsx->cellFormats[$r['s']];

如果 xlsx 的 cellXfs 定义少于单元格引用的 s 索引，会报 Undefined offset。生产环境建议关掉 notice 显示，或在调用前 @ 抑制。

✅ 已修复：配套补丁在取值前补了 isset() 保护，缺失索引自动填 ['format'=>null,'align'=>0]。

🟡 坑 10：合并单元格不返回

mergeCells 完全不解析。合并区域只有左上角单元格有值，其余是空。如果你依赖合并单元格的"填充"效果，需要自己处理：

$last = null;
foreach ($rows as $r) {
    $r[0] = $r[0] !== '' ? $r[0] : $last;   // 简单向下填充
    $last = $r[0];
}

✅ 已解决：配套扩展 SimpleXLSXPro 完整解析 mergeCells，CSV/TSV/JSON 会把值拆分复写到 x*y 每个格，HTML 输出真正的 colspan/rowspan。详见 十九、合并单元格与多格式导出。

🟢 坑 11：ZIP64 限制

1.1.18 起支持 ZIP64 数据描述符，但单个条目超过 4GB 仍会返回错误 6 "ZIP64 entry is too large to process"。正常 xlsx 不会碰到。

🟢 坑 12：命名空间前缀的正则清理

getEntryXML() 用一串正则去掉 XML 命名空间：

$entry_xml = preg_replace('/xmlns[^=]*="[^"]*"/i', '', $entry_xml);
$entry_xml = preg_replace('/[a-zA-Z0-9]+:([a-zA-Z0-9]+="[^"]+")/', '$1', $entry_xml);
$entry_xml = preg_replace('/<[a-zA-Z0-9]+:([^>]+)>/', '<$1>', $entry_xml);

这是"脏但快"的做法。对于极不规范的 XML 可能误伤。如果遇到 errno=3，可以打印清理后的 XML 排查。

🟢 坑 13：空行正则优化

对 sheet XML 会正则删除"整行都是空 <c/>"的行：

$entry_xml = preg_replace('/<row[^>]+>\s*(<c[^\/]+\/>\s*)+<\/row>/', '', $entry_xml, -1, $cnt);

副作用：行号不再连续。rows() 会补齐空行（靠 getIndex() 算出的 y 坐标），所以一般没问题；但如果你直接遍历 worksheet()->sheetData->row，要注意行号有跳。

14.2 用第一行做键名（关联数组）

官方示例，最常用：

function xlsxToAssoc(SimpleXLSX $xlsx, int $sheet = 0): array {
    $header = [];
    $rows   = [];
    foreach ($xlsx->readRows($sheet) as $k => $r) {
        if ($k === 0) { $header = $r; continue; }
        $rows[] = array_combine($header, $r);
    }
    return $rows;
}

加强版（处理列数不等、重复表头、空表头）：

function xlsxToAssocSafe(SimpleXLSX $xlsx, int $sheet = 0): array {
    $header = [];
    $rows   = [];
    foreach ($xlsx->readRows($sheet) as $k => $r) {
        if ($k === 0) {
            $seen = [];
            foreach ($r as $i => $h) {
                $h = trim((string)$h);
                if ($h === '') { $h = 'col_' . $i; }
                if (isset($seen[$h])) { $h .= '_' . (++$seen[$h]); }  // 重名加后缀
                $seen[$h] = 0;
                $header[$i] = $h;
            }
            continue;
        }
        $row = [];
        foreach ($header as $i => $h) {
            $row[$h] = $r[$i] ?? null;      // 缺列补 null
        }
        $rows[] = $row;
    }
    return $rows;
}

14.3 XLSX → CSV（流式，适合大文件）

function xlsxToCsv(string $xlsxPath, string $csvPath, int $sheet = 0): int {
    $xlsx = SimpleXLSX::parse($xlsxPath);
    if (!$xlsx) { throw new RuntimeException(SimpleXLSX::parseError()); }

    $fp = fopen($csvPath, 'wb');
    fwrite($fp, chr(0xEF) . chr(0xBB) . chr(0xBF));   // UTF-8 BOM

    $n = 0;
    foreach ($xlsx->readRows($sheet) as $r) {
        fputcsv($fp, $r);
        $n++;
    }
    fclose($fp);
    return $n;
}

function xlsxToHtml(SimpleXLSX $xlsx, int $sheet = 0, int $limit = 0): string {
    $s = '<table border="1" cellpadding="3" style="border-collapse:collapse">' . "\n";
    $y = 0;
    // 注意：readRowsEx 的 $limit 有 bug（见坑 1），这里自己计数
    foreach ($xlsx->readRowsEx($sheet) as $r) {
        if ($limit > 0 && $y >= $limit) { break; }
        $s .= '<tr>';
        foreach ($r as $c) {
            $tag = ($y === 0) ? 'th' : 'td';
            $css = sanitizeCss($c['css']);
            $v   = htmlspecialchars((string)$c['value'], ENT_QUOTES, 'UTF-8');
            $v   = preg_replace('/\R/', "<br>\n", $v);
            $s .= '<' . $tag . ' style="' . $css . '">'
                . ($v === '' ? '&nbsp;' : $v)
                . '</' . $tag . '>';
        }
        $s .= "</tr>\n";
        $y++;
    }
    return $s . '</table>';
}

function importUsers(PDO $pdo, string $tmpFile): array {

        return ['ok' => false, 'msg' => SimpleXLSX::parseError()];

        'INSERT INTO users (name, phone, id_card, amount, created_at) VALUES (?,?,?,?,?)'
    );

    $ok = $fail = 0;
    $errors = [];

    $pdo->beginTransaction();
    foreach ($xlsx->readRows() as $k => $r) {
        if ($k === 0) { continue; }                     // 跳过表头

        $name  = trim((string)($r[0] ?? ''));
        $phone = trim((string)($r[1] ?? ''));
        $idcard= trim((string)($r[2] ?? ''));
        $amount= is_numeric($r[3] ?? null) ? (float)$r[3] : null;
        $ctime = ($r[4] ?? '') ?: date('Y-m-d H:i:s');

        if ($name === '') { $errors[] = "第 {$k} 行：姓名为空"; $fail++; continue; }

        $stmt->execute([$name, $phone, $idcard, $amount, $ctime]);
        $ok++;

        if ($ok % 500 === 0) { $pdo->commit(); $pdo->beginTransaction(); }
    }
    $pdo->commit();

    return ['ok' => true, 'imported' => $ok, 'failed' => $fail, 'errors' => array_slice($errors, 0, 20)];

14.8 推荐的封装类

把上面的坑一次性处理掉：

<?php
use Shuchkin\SimpleXLSX;

// 需要 PHP 7.4+（用了箭头函数与属性类型声明）
class XlsxReader
{
    private SimpleXLSX $xlsx;
    private string $source;
    private bool $isData;
    private int $maxRows;

    public function __construct(string $pathOrData, bool $isData = false, int $maxRows = 100000)
    {
        $this->maxRows = $maxRows;
        $this->source  = $pathOrData;
        $this->isData  = $isData;
        $x = $isData ? SimpleXLSX::parseData($pathOrData) : SimpleXLSX::parse($pathOrData);
        if (!$x) {
            throw new RuntimeException(
                'XLSX 解析失败 [' . SimpleXLSX::parseErrno() . ']: ' . SimpleXLSX::parseError()
            );
        }
        $this->xlsx = $x;
    }

    /** 逐行产出，自动跳过全空行，自动限流 */
    public function rows(int $sheet = 0): Generator
    {
        $n = 0;
        foreach ($this->xlsx->readRows($sheet) as $r) {
            if (++$n > $this->maxRows) { return; }
            if (array_filter($r, static fn($v) => $v !== '' && $v !== null) === []) {
                continue;   // 跳过全空行（防御 dimension 不准）
            }
            yield $r;
        }
    }

    /** 带表头的关联数组 */
    public function assoc(int $sheet = 0): Generator
    {
        $header = null;
        foreach ($this->rows($sheet) as $r) {
            if ($header === null) {
                $header = array_map(
                    static fn($h, $i) => trim((string)$h) === '' ? "col_$i" : trim((string)$h),
                    $r, array_keys($r)
                );
                continue;
            }
            $row = [];
            foreach ($header as $i => $h) { $row[$h] = $r[$i] ?? null; }
            yield $row;
        }
    }

    /** 带样式的单元格，已修复 css 累加 bug 与 href 安全 */
    public function rowsEx(int $sheet = 0): Generator
    {
        // 重新 parse 一个干净实例，避免 css 引用污染（见坑 2）
        $ex = $this->isData ? SimpleXLSX::parseData($this->source) : SimpleXLSX::parse($this->source);
        if (!$ex) { throw new RuntimeException(SimpleXLSX::parseError()); }

        $n = 0;
        foreach ($ex->readRowsEx($sheet) as $r) {
            if (++$n > $this->maxRows) { return; }
            foreach ($r as &$c) {
                $c['css']  = $this->dedupeCss($c['css']);
                $c['href'] = $this->safeHref($c['href']);
            }
            unset($c);
            yield $r;
        }
    }

    private function dedupeCss(string $css): string
    {
        $parts = array_filter(array_map('trim', explode(';', $css)));
        return implode(';', array_unique($parts)) . ';';
    }

    private function safeHref(string $href): string
    {
        return preg_match('#^(https?://|mailto:)#i', $href) ? $href : '';
    }

    public function sheetNames(): array { return $this->xlsx->sheetNames(); }
    public function sheetsCount(): int  { return $this->xlsx->sheetsCount(); }
    public function dimension(int $s = 0): array { return $this->xlsx->dimension($s); }
}

十八、公式计算（XLSXFormula）

原版不计算公式，只读 Excel 写进去的缓存值（<c><f>SUM(A1:A3)</f><v>60</v></c> 里的 <v>）。一旦文件由 openpyxl / 自研程序生成，缓存值就是空的，value 全是 ''。

XLSXFormula 是一个纯 PHP 的公式求值器，配合 SimpleXLSXPro 可以直接算出结果。

18.1 基本用法

use Shuchkin\SimpleXLSXPro;

$xlsx = SimpleXLSXPro::parse('demo.xlsx');

// 1) 算某个单元格

// 3) 遍历所有含公式的单元格
foreach ($xlsx->calculatedCells(0) as $coord => $info) {
    printf("%s %s => %s\n", $coord, $info['formula'], $info['value']);
}

// 4) rowsPro() 里每个单元格都带 calculated 字段
foreach ($xlsx->readRowsPro(0) as $row) {
    foreach ($row as $c) {
        if ($c['f'] !== '') {
            echo $c['name'], ' = ', $c['calculated'], "\n";
        }
    }
}

20.1 两种图片来源

来源 特征 定位方式

两种都支持。

20.2 用法

// Img/sheet1_F8_2.png  cell=F8  source=xl/media/image2.png

20.5 注意事项

  • 提取成功后该 media entry 会被 deleteEntry() 释放，大图不会常驻内存
  • 图片提取发生在 extractImages() 调用时，不调用就不落盘，也不占磁盘

写在最后

SimpleXLSX 的价值在于恰到好处：它把"读 Excel"这件事做到了 80 分，代价是零依赖和一个 rows() 就能上手。剩下的 20 分（公式计算、图表、精确排版）如果你需要，那就该换 PhpSpreadsheet 了 —— 但大多数导入场景，你并不需要。

使用中最容易出事的三个点，再说一遍：

  1. 数字格式：前导零、身份证号、长数字，一定要在 Excel 源头上设为文本；
  2. 公式：拿不到值很正常，库不计算公式；
  3. 安全：渲染用户上传的 xlsx 前，href 必须自己过滤，且版本要 >= 1.1.19。
